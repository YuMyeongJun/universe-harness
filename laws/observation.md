# 관측 법칙 (Observation)

> **잰 것만 사실이다.**

이 법칙이 이 우주가 앞선 두 정원과 갈리는 지점이다. 정원들은 형식(frontmatter·필수 절)을
검사하지만 **동작은 사람이 본다.** 이 우주는 기계가 잰다.

## 규칙

1. **수치를 적을 때는 재는 명령을 함께 적는다.** 명령 없는 수치는 낡고, 낡은 수치는 거짓이 된다.
2. **추정으로 결론 내지 않는다.** 산출물·설정 파일·워크플로가 진실이다.
3. **파이프 뒤에서 종료코드를 읽지 않는다.**
   ⛔ `yarn lint | tail` · `node observatory/observe.mjs | sed -n '1,20p'` · `bash verify-laws.sh | grep ❌`
   파이프라인의 `$?` 는 **마지막 명령의 것**이다. `tail`·`sed`·`head` 는 거의 언제나 0 을 내므로
   **실패가 「exit 0」으로 보인다.** `grep` 은 더 나쁘다 — 실패 줄을 못 찾으면 1 을 내서
   **성공을 실패로도, 실패를 성공으로도** 뒤집는다.
4. **출력을 걸러 보고 통과를 선언하지 않는다.** §3 과 **다른 결함**이다.
   저쪽은 *종료코드*를 잘못 읽는 것이고, 이쪽은 **관측 범위**를 잘라 실패를 시야 밖에 두는 것이다.
   `| grep '❌'` 가 조용한 것은 「위반 없음」이 아니라 「**❌ 라고 적힌 줄이 없음**」이다.
   스크립트가 `ReferenceError` 로 죽어 **아무것도 세지 못했을 때도 똑같이 조용하다.**
   필터는 있는 것을 보여 주는 대신 **없는 것을 못 보게 만든다** — 크래시·스택트레이스·
   「0개 검사함」은 전부 필터가 지우는 쪽에 있다.
5. **작은 표본의 통과는 통과가 아니다.** 새 법칙은 실제 은하에 걸고 표본을 눈으로 세라.
6. **죽은 빌드 위의 수치는 전부 거짓이다.** 게이트가 빨간불이면 채점하지 않는다.
7. **도구가 모르는 입력을 조용히 삼키면, 안 켜진 모드가 켜진 것처럼 보인다.**
   §3·§4 는 *출력*을 잘못 읽는 것이지만, 이것은 **입력이 애초에 전달되지 않은 것**이다.
   실측: 존재하지도 않는 `--oracle` 을 「LLM 안 쓰는 모드」로 믿고 돌렸다. 파서가 모르는
   `--x` 를 전부 boolean 으로 삼켜서 **평범한 LLM 에피소드가 돌았고 돈이 나갔다.**
   비용을 기록하기 전까지 아무도 몰랐다 — 화면에 뜬 것은 전부 정상이었다.
   ⇒ 도구는 **모르는 플래그를 거부**하고, 값을 쓰는 쪽은 **자기가 실제로 쓴 자원을 기록**한다.
   기록하지 않은 자원은 재지 못하고, 재지 못하는 것은 새어도 모른다.
8. **재는 도구가 0을 쟀으면, 그것이 무죄인지 고장인지 말해야 한다.**
   하루에 같은 형태로 다섯 번 당했다 —
   `quality/cohesion` 0건(정규식 가정 3개가 틀림 · 실제 21건) ·
   `a11y/img-alt` 0건(패턴에 `NEVERMATCH` 가 커밋됨) ·
   변이 시험이 안 먹음(제목 형태가 달라 치환 실패) ·
   성운 페이지가 배포판 템플릿(조건을 엉뚱한 값으로 잡음) ·
   링크 검사가 코드블록을 링크로 셈.
   **전부 화면은 정상이었다.** 0은 「위반 없음」과 「훑개 고장」 둘 다이고,
   도구가 안 갈라 주면 사람은 언제나 앞엣것으로 읽는다.

   ⚠️⚠️ **0이 아닐 때가 더 위험하다.** Nuxt 저장소에 우주를 깔아 봤더니 코드 파일 217개 중
   `.vue` 95개(**44%**)를 규칙이 아예 안 읽는데 **105건이 보고돼** 정상으로 보였다.
   0이면 누군가 의심이라도 하지만, 수치가 나오면 아무도 분모를 묻지 않는다.
   ⇒ **재는 도구는 분자만이 아니라 분모를 말해야 한다** — 무엇을 읽었고 무엇을 못 읽었는지.
   `universe init` 은 깔면서 못 읽는 비율을 말하고, `universe observe` 는 은하가
   그 확장자를 판단하기 전까지 초록불을 주지 않는다.
   ⇒ 훑개는 **자기가 몇 개를 훑었는지** 함께 내고, 훑은 것이 0이면 실패로 끝낸다.
   ⇒ 변이가 대상에 안 먹었으면 **통과가 아니라 「시험이 낡았다」**로 낸다.
9. **이름이나 문자를 열거해 재면, 열거 밖은 영영 안 보인다.**
   같은 고장이 **네 번** 났고 처방도 매번 같았다:

   | 규칙 | 무엇을 열거했나 | 못 본 것 |
   |---|---|---|
   | `a11y/accessible-name` | `svg` · `Icon*` | `IcClose` · `Icons.IcX` — **전부**(0건이었다) |
   | `quality/nested-ternary` | `?` 를 셈 | `??` · `?.` 를 삼항으로 오인 — **136/153** |
   | `a11y/input-label` | 소문자 `input` | 감싼 `<Input>` — **입력의 94%** |
   | `tailwind/arbitrary-value` | 유틸리티 접두사 | `min-w-` · `leading-` · `grid-cols-` — **500건 넘게** |

   넷 다 **자기 코드에서는 안 보였다.** 우리가 안 쓰는 작명은 우리 말뭉치에 없기 때문이다.
   ⇒ **의미로 잡아라** — 「자기 닫는 요소뿐이고 글자가 없다」 · 「`placeholder` 가 있다」 ·
   「`무엇이든-[값]`」. 무엇으로 불리든 통한다.
   ⇒ 언어가 정한 이름(`div` · `button` · `className`)은 열거해도 된다. **사람이 정하는 이름**이
   위험하다.
   ⇒ ⚠️ **의미로 잡기도 만능이 아니다.** 중첩 대괄호 하나가 샜다 — 그래서 **남의 코드로
   확인**하기 전에는 「고쳤다」고 하지 않는다.

## 검사를 판정하는 법

판정과 요약은 **다른 일이고, 순서가 있다.** 걸러 보는 것 자체가 금지는 아니다 —
**판정 전에** 거르는 것이 금지다.

```bash
# ① 파이프 없이 그대로 돌린다. 출력 전체가 화면에 남아야 한다.
bash observatory/verify-laws.sh
# ② 종료코드는 바로 다음 줄에서 읽는다. 사이에 아무 명령도 넣지 않는다.
echo "exit=$?"
# ③ 출력을 처음부터 끝까지 지나간다 — 특히 검사 개수와 마지막 줄.
# ④ 필터는 ③ 을 한 뒤에, 요약을 남기려고만 쓴다.
```

출력이 너무 길면 **파이프 대신 파일로 떨어뜨린다.** 리다이렉션은 종료코드를 보존한다:

```bash
node observatory/observe.mjs > /tmp/observe.log 2>&1; echo "exit=$?"
grep -c '❌' /tmp/observe.log     # 판정이 끝난 뒤의 요약이다
```

⚠️ `set -o pipefail` 이나 `${PIPESTATUS[0]}` 로 §3 은 막을 수 있지만 **§4 는 못 막는다.**
종료코드가 맞아도 걸러 본 출력은 여전히 관측이 아니다. 「초록불이면 안 읽는다」가
두 번을 다 놓치게 만든 습관이다.

## 왜 — 실측 근거

### 오탐은 큰 표본에서만 보인다

이 우주의 재료가 된 규칙들은 셀프테스트의 작은 표본에서 **오탐 0** 이었다.
1,227개 파일에 걸자 **오탐 4종·153건**이 드러났다:

| 오탐 | 원인 |
|------|------|
| `templateImageRatioLabel` 을 「의도 없는 이름」으로 | `temp\w*` 가 `template…` 을 통째로 먹었다 |
| `useState(180)` 을 「복사본 state」로 | 초기값이 prop 인지 확인하지 않았다 |
| `import { useState } …` 를 복사본 state 로 | 정규식이 줄바꿈을 넘어 다음 괄호를 먹었다 |
| `bg-[var(--ui-primary-light)]` 를 「임의 값」으로 | **토큰을 쓰고 있는 코드**를 벌하고 있었다 |

마지막 것이 특히 나빴다 — 관문이 **지키라는 것을 지킨 코드를 막고** 있었다.

### 이 법칙은 두 라운드 연속으로 밟혔다

§3 이 이미 있는데도 밟혔다. 한 번은 사고고 두 번은 습관이므로 여기 이름을 남긴다.

| 언제 | 무엇을 했나 | 무엇을 놓쳤나 | 어느 규칙 |
|------|------------|--------------|----------|
| **2026-09-04 · R04** | 드리프트 탐지 시험에서 검사 출력을 `grep` 으로 걸러 봤다 | 스크립트가 `ReferenceError` 로 **크래시했는데** 걸러 본 화면은 조용했다. 초록불로 읽었다 | §4 (관측 범위) |
| **2026-09-04 · R05** | 빅뱅 관문의 음성 시험에서 `node … \| sed -n …` 뒤의 `$?` 를 읽었다 | 실제 종료코드는 **1**, 읽은 값은 **0**. 무는 관문을 「안 문다」로 볼 뻔했다 | §3 (종료코드) |

R04 는 종료코드를 제대로 읽었어도 못 잡았다 — **크래시는 종료코드가 아니라 출력에 있었다.**
그래서 §3 하나로는 부족하고 §4 가 따로 있어야 한다.
기록: `log/2026-09-04-21-30-r04-forces-orbits-redshift.md` · `log/2026-09-04-22-10-r05-bigbang.md`

## 재는 법

법칙마다 「재는 법」 절이 있다. 없으면 그것은 법칙이 아니라 의견이다.

이 법칙 자신은 관측소가 정적으로 훑는다 — 저장소의 스크립트가 **검사 명령을 파이프에 물려**
그 결과로 판정하는지 본다.

```bash
bash observatory/verify-laws.sh      # 「파이프 뒤 판정」 절을 보라
echo "exit=$?"

node observatory/verify-checks.mjs   # §7 — 진입점이 모르는 플래그를 거부하는가
echo "exit=$?"                       #      그리고 검사들이 정말 무는가(변이 시험)
```

⚠️ **§7 은 오래 규칙만 있고 관문이 없었다.** 재는 법이 `argv.ts` 한 곳에만 붙어 있었고,
세어 보니 진입점 6곳이 **전부** 모르는 플래그를 삼키고 있었다. 규칙은 관문이 될 때까지
규칙이 아니다.

⚠️ 이 항목은 **경고까지만** 낸다(`exit 1` 로 막지 않는다). 스크립트를 정적으로 읽어서는
파이프라인의 종료코드가 실제로 *판정에 쓰이는지* 화면에 뿌리기만 하는지 구분할 수 없기 때문이다.
경고가 뜨면 사람이 그 줄을 열어 확인한다. 근거 없이 무는 관문은 무시하는 법부터 가르친다(`laws/README.md`).

## 위반 시

수치를 지우고 다시 잔다. **판정도 지운다** — 걸러 본 화면 위에서 내린 「통과」는
수치보다 먼저 버려야 하는 것이다.
