# 궤도 (Orbits)

> 법칙은 무엇이 옳은지 말하고, 힘은 그 일을 하고, **궤도는 그것이 반복되게 한다.**

한 번 하고 끝나는 일은 궤도가 아니다. **다음 바퀴가 있는 것만** 여기 적는다.

## 무엇이 여기 사는가

| 궤도 | 무엇이 도나 | 한 바퀴의 끝 |
|------|------------|-------------|
| [라운드](round.md) | 작업 → 평가 → **낮은 축이 다음 바퀴의 입력이 된다** | 성운에 항목이 올라간다 |
| [관측→전파](observe-and-broadcast.md) | 재기 → 기준선 갱신 → 발행 | 위키가 저장소와 같아진다 |
| [성운→법칙→별](nebula-to-star.md) | 관측 → 법칙 승격 → 별 수정 | 위반 수가 준다 |

## 새 궤도를 낼 때

1. `orbits/{name}.md` — 흐름도(mermaid) + 단계 + **한 바퀴의 끝**을 적는다.
2. 「한 바퀴의 끝」이 무엇인지 못 적겠으면 그것은 궤도가 아니다. 절차일 뿐이다.
3. `universe.config.json` 의 `orbits` 배열에 등재한다.

## 함정 — 궤도가 없으면 제안이 로그에만 쌓인다

앞선 정원의 로그에 답이 있다. 그래서 그쪽 로그 템플릿에 이런 규칙이 있다:

> 다음 단계 제안은 쌓아두지 않는다 — 실행할 제안은 **작업 보드로 승격**한다.
> 로그에만 남은 제안은 실행되지 않는다.

이 우주도 같은 함정에 빠져 있었다. R01~R03 의 평가에서 낮은 축이 나왔는데
(자동화 C · 드리프트 원인 미규명) **로그에만 있었다.**
성숙도가 L4 에서 멈춰 있던 이유가 그것이다 — L5 의 조건은 「낮은 평가가 다음 라운드의
작업이 된다」다. **[라운드 궤도](round.md)가 그 경로다.**
