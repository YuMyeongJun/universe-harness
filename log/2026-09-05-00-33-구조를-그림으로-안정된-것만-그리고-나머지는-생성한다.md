# R18 — 구조를 그림으로

## 실행 요약

사용자 요청 — **「아키텍처도 그림으로, 폴더구조도, 시퀀스 다이어그램도. 이건 제일 후순위야」**.

성운에 「구조가 아직 움직이는 중이라 지금 그리면 낡는다」고 적어 뒀었다.
다시 보니 **절반만 맞았다.**

| 무엇 | 안정성 | 판단 |
|---|---|---|
| 다섯 층 · 기관 · 라운드 궤도 | 안 바뀜 | 이미 SVG 로 있었다 |
| **배달 경계 · 빅뱅 3단계 · 관문→게이트** | 안 바뀜 | **그렸다** |
| 명령 목록 | 오늘만 다섯 늘었다 | ⛔ **안 그렸다** — 그리면 낡는다 |
| 폴더 구조 | 바뀜 | 🟡 **생성한다** |

**개념 구조는 한 번도 안 바뀌었고 움직인 것은 명령 표면뿐이었다.**
그래서 안정된 것만 그리고, 움직이는 것 중 하나(폴더)는 생성으로 돌렸다.

## mermaid 로 쓴 이유

텍스트라 **diff 가 되고 생성할 수 있다.** SVG 는 바뀌었는지 사람이 못 본다.

## 그림이 낡는 문제를 어떻게 다뤘나

| 방법 | 어디에 |
|---|---|
| **안 그린다** | 자주 바뀌는 명령 목록 |
| **생성한다** | 폴더 구조 — `universe structure` 가 파일시스템에서 만든다 |
| **낡으면 잡는다** | `--check` 를 `round close` 와 변이 시험에 물렸다 |
| **고아를 잡는다** | 어디서도 안 걸린 그림은 낡아도 아무도 모른다(R17 에서 만든 검사) |

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | A | 폴더 구조가 낡으면 실제로 잡힌다 — 폴더를 하나 만들면 exit 1, 치우면 exit 0. 변이 시험(검사 5종 · 변이 9건)에도 넣었다 |
| 실측 기반성 | A | 배달 경계 그림은 **`bin/init.mjs` 의 실제 목록**(DELIVERED · EMPTY · SEEDED · EXCLUDE)에서 읽어 그렸다. 기억으로 그리지 않았다 |
| 변경 정직성 | A | **안 그린 것과 그 이유**를 문서 첫 줄에 적었다 — 「명령 목록처럼 자주 느는 것은 일부러 안 그렸다. 낡은 그림은 없는 그림보다 나쁘다」. 성운의 내 옛 판단이 절반 틀렸다는 것도 적었다 |
| 낡음 저항 | A | 그림 넷 중 하나는 생성되고 셋은 개념이라 안 바뀐다. 생성기 자신에도 바닥값을 뒀다(폴더를 하나도 못 훑으면 실패) |
| 도달성 | B | 이 그림들은 **저장소에서만 보인다.** 위키(beacon)로는 mermaid 가 코드블록으로 나가고 SVG 는 상대 경로라 안 뜬다 — 사용자가 컨플루언스에서 볼 수는 없다 |

## 다음 단계

위키에서도 그림이 보이게 하려면 — Confluence 가 mermaid 매크로를 지원하는지 재거나,
SVG 를 첨부로 올려 참조해야 한다. **먼저 되는지부터 재는 것**이 R17 에서 배운 순서다.
