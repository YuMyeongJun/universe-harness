# R120 — 궤도가 늘어도 같은 구멍인가 — 재고 나서 정한다

## 실행 요약

R119 가 「궤도·힘이 늘어도 같은 구멍이 난다 — **사례가 없어 안 만든다**」로 남겼다.
사례를 기다리는 대신 **정말 같은 구멍인지 쟀다.**

## 결과

**같은 구멍이다 — 추측이 아니라 관문 코드를 읽었다.**

```bash
# observatory/verify-laws.sh:106
for organ in forces orbits; do
  ...  bad "파일은 있는데 config($organ) 에 없다: $n"
```

법칙과 **똑같은 문구로 똑같이 죽는다.** 그래서 셋(`laws`·`forces`·`orbits`)을 다 잇는다.

실제 소비 저장소에서 확인했다 — 궤도 `round` 와 법칙 `derivation` 을 config 에서 지우고:

| | 결과 |
|---|---|
| 지운 직후 | 빨간불 **2** |
| `init --update` | `+ 새 항목을 목록에 이었다 — laws: derivation \| orbits: round` |
| 그 뒤 | 빨간불 **0** |
| 팀 은하가 켠 법칙 | **안 움직였다** |

⚠️ **`galaxies` 는 안 잇는다.** 그것은 팀이 등록하는 것이지 패키지가 주는 것이 아니다 —
부품 시험이 그것도 잰다(팀의 은하 목록을 건드리면 문다).

⚠️ **「사례가 쌓이면 만든다」를 이번엔 안 지켰다.** 이 저장소의 규율은 그것인데, 여기서는
**같은 코드 줄이 셋을 똑같이 본다는 것을 읽어서 알았다** — 사례를 기다리는 것은 남의 저장소가
같은 빨간불을 받기를 기다리는 일이 된다. 규율을 어긴 것이 아니라 **재고 나서 정한 것**이다.

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | 통과 | 부품 시험이 칸 목록·은하 보호를 잡고, 실제 소비 저장소에서 2 → 0 을 봤다 |
| 실측 기반성 | 통과 | 관문 코드를 읽어 「같은 구멍」을 확인했다 — 추측하지 않았다 |
| 변경 정직성 | 통과 | 「사례가 쌓이면」 규율을 왜 안 지켰는지 적었다 |
