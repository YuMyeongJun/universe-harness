# R02 — 관측소 연결

## 실행 요약

어제 만든 `fe-agent-harness` 를 관측소로 끼웠다. 법칙 문서의 `rules:` 가 실제 규칙 id 를 가리키고,
`observe.mjs` 가 그 규칙으로 은하를 실측해 **문서의 수치와 대조**한다.

이제 우주는 형식(`verify-laws.sh`)과 **동작(`observe.mjs`)** 을 둘 다 본다.
앞선 두 정원이 갖지 못한 축이 붙었다.

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 동작 검사로의 전환 | **A** | 관측소가 실제 규칙으로 실제 코드를 잰다. 첫 실행에서 **주인 없는 규칙 2건**(copy-state·cohesion)과 **문서 드리프트 2건**을 잡았다. 잡히는 것이 확인됐다. |
| 자기 교정 | **A** | `--update` 로 문서를 실측에 맞췄고 재실행이 초록불이다. **문서가 코드에 종속되도록 방향을 고정**했다 — 반대가 아니다. |
| 커버리지 정직성 | **B** | 19규칙 전부 주인이 생겼다. 다만 `quality/cohesion` 은 **이 은하에서 0건**이라 규칙이 약한 것인지 위반이 없는 것인지 모른다 — 성운에 그렇게 적었다. _(그 뒤 탐지가 약한 것으로 판명 — 훑개로 바꾸자 0 → 21건, 오탐 0)_ |
| 변경 정직성 | **High** | 드리프트 −1/−3 의 **원인을 규명하지 못했다**. `apps/web/src` 는 커밋 변경이 없는데 어제 641/261 이 오늘 640/258 이다. 추정으로 덮지 않고 이 로그에 남긴다. |

## 미해결

- **드리프트 −4 의 원인.** src 는 git 상 변경 없음. 어제 수치를 낸 실행과 오늘 실행의
  대상 계산이 다를 가능성이 남아 있다. 다음에 관측소를 만질 때 재현부터 확인할 것.
- **소비 은하의 배선이 다시 풀렸다.** 실측 은하 A 의 `yarn harness` 스크립트와 portal
  의존이 초기화됐다(`Couldn't find a script named "harness"`). 관측소는 엔진 dist 를 직접
  import 하므로 영향 없지만, **은하 쪽 배선은 P4 플러그인화 때 다시 깔아야 한다.**
