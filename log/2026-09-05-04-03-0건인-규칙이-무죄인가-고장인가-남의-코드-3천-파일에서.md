# R26 — 0 은 무죄가 아니라 고장이었다

## 실행 요약

R25 가 남긴 것: 규칙 20개 중 **둘**만 남의 코드로 쟀다. 하나씩 하는 대신
**한 번에 걸고 0건인 것을 찾았다** — 관측 법칙 §8 의 질문을 규칙 전체에 던진 것이다.

3,058 파일 · 규칙 14개 중 **0건은 하나**였다: `a11y/accessible-name`.

## 고장이었다

패턴이 `svg` 와 `Icon*` 라는 **한 가지 작명만** 알고 있었다:

| 코드 | 예전 |
|---|---|
| `<button><svg /></button>` | 잡음 |
| `<button><IcClose /></button>` | **못 잡음** ← 실제 코드 |
| `<button><Icons.IcX /></button>` | **못 잡음** ← 실제 코드 |

작명을 열거하는 대신 **의미로 잡게** 고쳤다 — 버튼 안이 자기 닫는 요소뿐이고 글자가
없으면 접근 가능한 이름이 없다. **0 → 11건**, 표본은 전부 진짜였다.

## 그 고침이 새 오탐을 들여왔고, 관문이 잡았다

`<button><img alt="상품 이미지" /></button>` 는 **이름이 있다** — `alt` 가 그것이다.
내 새 패턴이 이것까지 잡았고, **커밋 관문(엔진 계약 규칙 시험)이 커밋 전에 막았다.**

R09 에서 그 관문을 만든 이유가 정확히 이것이다. 없었으면 「고쳤다」면서 새 오탐을
들여놨을 것이다.

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 문제 발견 | A | 규칙을 하나씩 재는 대신 **전체에 §8 을 던졌다** — 「0건인 것이 있는가」. 한 번에 재서 하나를 찾았고 그것이 진짜 고장이었다 |
| 집행 가능성 | A | 양방향 9/9. **남의 코드에서 0 → 11건**이 진짜 증명이다 — 합성 시험만으로는 「작명을 하나만 안다」를 못 잡았을 것이다 |
| 관문의 값 | A | 내가 넣은 새 오탐을 **커밋 관문이 커밋 전에 막았다.** 관문이 값을 한 것을 로그에 남긴다 |
| 변경 정직성 | A | 「고쳤다」가 아니라 「고치다 새 오탐을 넣었고 관문이 잡았다」로 적었다. 회귀 시험의 known-positive 도 **실제 작명**으로 바꿔 「통과할 만한 것을 재게」 했다 |
| 남은 규칙 | B | 0건이던 것은 고쳤지만, **0이 아닌 규칙들의 표본은 대부분 안 봤다.** `naming-intent` 141건 · `nested-ternary` 153건 · `cohesion` 41건이 진짜인지 모른다 |
