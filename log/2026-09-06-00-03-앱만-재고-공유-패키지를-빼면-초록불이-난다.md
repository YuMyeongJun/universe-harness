# R70 — 앱만 재고 공유 패키지를 빼면 초록불이 난다

## 실행 요약

좌표 예시에 이런 경고가 **처음부터** 적혀 있었다 —
「⚠️ 앱만 넣고 공유 패키지를 빼면, **별이 그것을 망가뜨려도 초록불이 난다.**」

**경고만 있고 검사는 없었다.** R69 가 만든 모노레포 은하로 확인했다.

## 결과

### ⛔ 앱이 쓰는 워크스페이스 패키지 셋이 전부 lint 밖이었다

```
⛔ 은하 heythere-admin — 앱이 쓰는 **워크스페이스 패키지 3개가 lint 밖**이다.
   · @lunasoft-org/front-core (packages/front-core) — 별이 이것을 망가뜨려도 **초록불이 난다**
   · @lunasoft-org/heythere-components (packages/components)
   · @lunasoft-org/heythere-models (packages/models)
```

⛔ **자동으로 넣지 않는다** — 그 패키지를 이 은하가 책임지는지는 팀이 정한다.
대신 **판단을 요구한다**(`sharedPackagesJudged`) — `blindJudged` 와 같은 방식이다.
좌표에 넷을 채우니 초록불이 됐다.

### ⛔ 그러다 lint 대상을 **엉뚱한 기준으로** 풀고 있는 것을 찾았다

R57 의 좌표 검사는 `lintTargets[].target` 을 **전부 `appDir` 기준**으로 풀었다.
공유 패키지 대상은 **자기 워크스페이스 기준**인데도.

앱에 같은 이름의 폴더가 있으면 **없는 경로여도 통과한다.** 재현했다 —
`@lunasoft-org/heythere-components` 의 대상을 `./src/components/pages` 로 두면
그 패키지엔 없지만 `apps/admin` 엔 있어서 **초록불**이었다.

⇒ 워크스페이스 이름 → 폴더 지도를 만들어 **자기 자리에서** 푼다. 이제 짚는다:

```
· lintTarget — @lunasoft-org/heythere-components 의 ./src/components/pages
```

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | 통과 | 둘 다 `observe` 에 걸었고 각각 exit 1 → 채우면 0 을 확인했다. 단일 앱 은하는 영향이 없다(확인) |
| 실측 기반성 | 통과 | 앱의 `dependencies` 와 워크스페이스 목록을 실제로 대조해 셋을 찾았다. 잘못된 기준은 **앱엔 있고 패키지엔 없는 경로**로 재현했다 |
| 변경 정직성 | 통과 | 「무는데 이유가 다를 수 있다」를 의심해 **한 번 더 시험한 것**이 두 번째 결함을 찾았다. 자동으로 lint 대상을 넣지 않은 이유도 적었다 |

## 다음 단계

- 이 검사는 **`dependencies` 에 적힌 것**만 본다. 워크스페이스 패키지를 상대경로로 import 하는
  저장소는 못 잡는다 — 그건 다른 방법이 필요하다.
