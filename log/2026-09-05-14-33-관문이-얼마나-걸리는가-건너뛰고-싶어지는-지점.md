# R50 — 관문이 얼마나 걸리는가 — 건너뛰고 싶어지는 지점

## 실행 요약

관문이 15종까지 늘었는데 **얼마나 걸리는지 한 번도 안 쟀다.**
느려지면 사람은 고치는 법이 아니라 **건너뛰는 법부터 배운다** — 이 저장소가 반복해 적어 온 말이다.
그런데 「빠를 것이다」는 짐작이었다.

## 결과

### 우주 자신은 싸다

| 무엇 | 시간 |
|------|-----:|
| 커밋 관문(빠른 것만) | **1.5초** |
| 관문 15개 합계 | **10.4초** |
| ↳ 변이 시험 하나 | 7.9초 (**76%**) — 자식 20개를 띄우니 당연하다 |
| 법칙 관측 — **1,404파일 은하** | **0.29초** |

⚠️ 「법칙 관측 0.06초」가 미덥지 않아 **출력까지 열어 확인했다**(2,314바이트의 정상 보고).
정적 규칙은 정말로 싸다 — 1,404파일에서도 0.3초다.

### 비싼 것은 은하의 도구 사슬이다

| bizmsg-backoffice-front (1,404파일) | 시간 |
|---|---:|
| `eslint ./src` | 7.9초 |
| `tsc --noEmit` | **3.9초** |
| `yarn build`(`tsc && vite build`) | **10.1초** |

R45 는 「`typecheck` 를 선언하면 가벼워진다」고 **적어만 뒀다.** 재 보니 참이었다 — **2.6배**.

### 재서 말하게 했다

컴파일 관문이 무거운 쪽(`build`)을 돌고 **5초를 넘기면**, 걸린 시간을 그대로 말하고
`commands.typecheck` 를 권한다.

```
✅ 별이 은하에서 선다 (9.3초).
   ⓘ 별 하나에 9.3초다. 타입 검사만 도는 명령이 있으면 `commands.typecheck` 에 적어라 …
      다만 타입 검사는 **더 적게 본다**(번들러에서만 깨지는 것은 못 본다). 무엇을 살지는 은하가 정한다.
```

⛔ **명령을 지어내 주지 않는다**(R45 의 규율). 그리고 **권하면서 잃는 것도 같이 말한다** —
싼 쪽만 말하면 그것은 권유가 아니라 유도다.

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | 통과 | 권유가 **측정값에 걸려 있다** — 5초를 넘길 때만, 실제 걸린 초를 넣어 말한다. 짐작으로 늘 뜨는 잔소리가 아니다 |
| 실측 기반성 | 통과 | 관문 15개를 하나씩 재고, 못 미더운 값(0.06초)은 출력을 열어 확인했다. R45 의 「가벼워진다」는 주장을 3.9 대 10.1 로 **검증**했다 |
| 변경 정직성 | 통과 | **결함을 못 찾은 라운드**다. 그렇게 적는다 — 시간표를 얻었고 R45 의 주장 하나를 검증했다. 권유에 **잃는 것**(번들러 오류를 못 본다)을 같이 적었다 |

## 다음 단계

- 변이 시험이 76%를 쓴다. 줄일 수 있지만 **줄일 이유가 아직 없다** — 10초는 라운드마다 한 번이다.
  값이 두 자릿수 초를 넘기면 그때 병렬로 돌릴지 본다.
