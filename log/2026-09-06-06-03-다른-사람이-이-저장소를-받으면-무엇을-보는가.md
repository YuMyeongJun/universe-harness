# R82 — 다른 사람이 이 저장소를 받으면 무엇을 보는가

## 실행 요약

R81 이 「`dist` 는 커밋 안 된다」를 확인했다. 그러면 **받은 사람은 무엇을 보는가.**
말로 답하지 않고 **실제로 클론해서** 돌렸다.

```
⛔ 18개 돌았다 — 빨간불 6개
```

**받은 사람은 깨진 도구를 본다.** `dist` 가 없는 것은 **정상**인데.

## 결과

R58 이 소비 저장소에 세운 규율(「여기선 못 잰다」)이 **이 자리에도 그대로 필요**했다.

⛔ **처음엔 문자열로 짐작했다** — 「관측 엔진을 찾지 못했다」가 출력에 있으면 못 잰 것으로.
6 → 3 으로만 줄었다. 나머지 셋은 **엔진 없이 다른 이유로** 죽어(의존성 미설치 · 자식 검사의 실패)
그 문구가 안 보였다.

⇒ **관문 자신이 말하게 했다** — `needsEngine: true`. 짐작이 아니라 선언이다.

| | 우리 저장소 | 갓 클론 |
|---|---|---|
| 돌린 검사 | 18 | **11** |
| 빨간불 | 0 | **0** |
| 엔진이 없어서 못 잼 | 0 | **7** |

그리고 **한 번만 말한다**:

```
⚠️ **엔진이 아직 없어 7개를 못 쟀다.** 갓 클론했다면 정상이다 — `dist` 는 커밋되지 않는다.
   한 번만 하면 된다:  cd observatory/engine && npm install && npm run build
```

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | 통과 | `needsEngine` 은 관문 목록에 있는 선언이라 새 검사를 만들 때 같이 정해진다. 갓 클론과 우리 저장소 양쪽에서 확인했다 |
| 실측 기반성 | 통과 | **진짜로 클론해서** 돌렸다. 첫 처방(문자열 짐작)이 6 → 3 까지만 줄이는 것도 재서 알았다 |
| 변경 정직성 | 통과 | 문자열 짐작이 **부족했다**는 것을 적었다. 「빨간불 0」이 아니라 **「7개는 못 쟀다」**로 말한다 — 안 잰 것을 잰 척하지 않는다 |
