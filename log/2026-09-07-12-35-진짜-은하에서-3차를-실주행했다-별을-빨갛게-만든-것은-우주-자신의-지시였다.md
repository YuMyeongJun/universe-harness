# R148 — 진짜 은하에서 3차를 실주행했다 — 별을 빨갛게 만든 것은 우주 자신의 지시였다

## 실행 요약

C3 — **진짜 은하에서 3차 팽창 첫 실주행.** 구독 경로(R145 보증), 모델 호출 있는 진짜 주행이다.

```
은하 backoffice · 태양계 brandmessage · 별 BrandMessageQuotaCard
요구사항: 브랜드메시지 발송 잔여 건수를 카드로 보여 주고, 잔여가 0이면 소진 배지를 띄운다
결과: 턴 10/10 소진 · 게이트 1회 · [NOT YET] · 되돌림(파일 4개 + 빈 폴더)
```

## 결과

### 에이전트는 잘했다 — 그리고 우주가 그것을 빨갛게 만들었다

lint 산출(원본 JSON)을 파일별로 갈라 봤다:

| 파일 | error | 규칙 |
|------|-------|------|
| `BrandMessageQuotaCard.tsx` | **0** | |
| `useBrandMessageQuotaCard.ts` | **0** | |
| `index.ts` | **0** | |
| `BrandMessageQuotaCard.feature.test.tsx` | **6** | `@typescript-eslint/no-unsafe-member-access` |
| (별 밖 — 은하의 트렁크) | 11 | 기준선 그대로 |

**구현 셋은 error 0 이다.** 별을 빨갛게 만든 것은 에이전트가 **추가한 테스트 파일 하나**고,
그 파일은 이 저장소에 `vitest`·`@testing-library/react` 가 없어서 타입이 `any` 로 풀린 것이다.

### 그 테스트 파일을 **우주가 시켰다**

같은 실행에서 1차 팽창은 이렇게 말했다:

```
⚠️ **행동 계약 파일(`*.test.tsx`)을 안 만들었다** — 이 은하는 테스트를 못 돌린다
   만들면 `tsc` 가 `vitest`·`@testing-library/react` 를 못 찾아 **빌드가 깨진다**(실측).
```

그리고 **200줄 뒤**, 같은 프로그램이 에이전트에게 준 브리핑에는 이렇게 적혀 있었다:

```
4. ✅ 요구사항이 **새 동작**을 더하면 그 동작을 검증하는 **새 테스트 파일**을 같이 내라
   (예: <별자리>/<Star>.feature.test.tsx)
```

에이전트는 **시킨 그대로** `BrandMessageQuotaCard.feature.test.tsx` 를 냈다. 파일 이름까지 예시 그대로다.
⇒ **프로그램이 200줄 앞에서 내린 판단을 브리핑이 뒤집었고, 그 값을 진짜 주행이 치렀다.**

⛔ 이것은 에이전트의 실수가 아니다. 규약 6번(「테스트가 곧 계약이다」)과 브리핑 4번을
따른 결과다. 도구가 **자기가 아는 사실을 말해 주지 않은 것**이다 —
`canRunTests` 는 1차가 이미 계산해서 쓰고 있었다.

**고쳤다**: 브리핑의 테스트 규칙을 `canRunTests` 로 갈랐다. 못 돌리는 은하에는
「⛔ 테스트 파일을 내지 마라 — 타입이 `any` 로 풀려 네 파일이 빨갛게 만든다.
이 별에는 지켜 줄 계약이 없다는 뜻이고, 그건 네가 고칠 수 있는 것이 아니다」라고 말한다.
근거는 1차와 **같은 값**을 쓴다 — 두 자리가 갈리면 또 뒤집힌다.

### R146 이 이 주행에서 값을 했다

게이트 출력에 이렇게 찍혔다:

```
❌ lint error 17 · warning 144
⚪ build     — 못 쟀다: 앞의 게이트가 빨간불이라 돌지 않았다
⚪ test      — 못 쟀다: 앞의 게이트가 빨간불이라 돌지 않았다
⚪ typecheck — 못 쟀다: 앞의 게이트가 빨간불이라 돌지 않았다
```

R146 **전이었다면** 화면은 `❌ lint` 한 줄뿐이었고, **에이전트도** build·test 가
통과한 줄 알았을 것이다. 못 잰 축을 말하는 것은 사람만을 위한 것이 아니었다.

### 턴 예산이 진짜 은하에서 어떻게 쓰이는가 (픽스처에선 안 보이던 것)

| 턴 | 무엇 |
|----|------|
| 1–7 | **probe** — 자매 별(`TemplateUsageCard`) 관례 · 배지 컴포넌트(`TextBadge`) · 시맨틱 토큰 · 테스트 관례 |
| 8 | patch (관문 통과 · 파일 4개) |
| 9 | submit → 게이트 |
| 10 | submit (바이트 그대로라 게이트 안 돎) — 예산 소진 |

**70%가 조사에 갔다.** 진짜 은하는 읽을 것이 많으니 당연하다 — 그런데 그 결과
**고칠 기회가 한 번도 없었다.** 게이트가 빨간불을 돌려준 뒤 남은 턴은 1회였고
그것으로는 못 고친다. 픽스처(4턴이면 끝)에서는 이 벽이 안 보인다.
⚠️ **성운에 올린다** — 조사와 수정이 한 예산을 나눠 쓰는 것이 옳은지.

### 에이전트가 증거를 잘못 읽었다 (도구가 옳게 준 증거를)

마지막 submit 에서 에이전트는 이렇게 적었다:
「내 새 파일(`…feature.test.tsx`)의 import 순서는 … **별도 규칙 위반이 지목되지 않았다**」.
그런데 게이트 피드백은 그 파일을 **`← 별`** 로 찍어서 돌려줬다.
도구는 옳게 말했고 에이전트가 잘못 읽었다. ⚠️ 성운에 올린다 —
귀속 표시가 「이 파일이 네 탓이다」로 더 분명해야 하는지.

### 남의 저장소 — 들어갈 때와 같은가

들어갈 때 3건. 나올 때 **같은 3건**. 되돌리기가 파일 4개 + 빈 폴더를 전부 지웠다
(R146 의 재-찍기 고침이 여기서도 값을 했다 — 에이전트가 고친 파일도 깨끗이 지워졌다).
커밋하지 않았다.

### 일부러 깨서 무는지 봤다

| 변이 | 물었나 |
|------|--------|
| 브리핑의 `canRunTests` 조건을 없애고 무조건 테스트를 시킴(결함 복원) | ✅ 부품 시험이 죽었다 — 「브리핑이 은하의 테스트 능력을 안 본다」 |
