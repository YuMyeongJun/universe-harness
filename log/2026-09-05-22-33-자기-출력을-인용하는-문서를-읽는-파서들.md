# R67 — 자기 출력을 인용하는 문서를 읽는 파서들

## 실행 요약

R66 이 로그에서 「**산문을 데이터로 읽는**」 함정을 찾았다. 이 저장소는 성운·법칙에도
자기 출력과 예시를 그대로 인용한다 — 같은 함정이 있는지 셌다.

| 파서 | 어떻게 읽나 | 판정 |
|------|-------------|------|
| `observe` → 성운 | **파일 전체 문자열**(`includes`) | ⛔ 닫힌 줄·산문·형식 예시를 다 센다 |
| `observe` → 법칙 `rules:` | frontmatter 만 | ✅ 안전했다 |
| `bigbang/engine` → 법칙 `rules:` | **파일 전체** 정규식 | ⛔ 잠재 결함 — **별의 관문**을 세우는 자리다 |
| `render-facts` → 법칙 `rules:` | 파일 전체 정규식 | ⛔ 같은 결함 |

## 결과

### ⛔ 닫힌 성운 줄도 주인으로 셌다

성운의 `quality/copy-state` 줄을 **취소선 + ✅ 닫힘**으로 바꾸고 관측을 돌렸다.

```
── 커버리지 — 규칙 20 · 법칙이 덮은 것 19 · 성운 1
  ✅ 주인 없는 규칙 없음
```

**닫힌 줄인데 주인이 있다고 한다.** 규칙이 법칙을 잃고 성운 항목마저 닫히면
**커버리지 구멍이 생기는데 화면은 초록불**이다.

⇒ 표 줄만 보고 **닫힌 줄은 빼고** 센다. 같은 시험을 다시 돌리면 이제 이렇게 나온다.

```
── 커버리지 — 규칙 20 · 법칙이 덮은 것 19 · 성운 0
  ❌ 주인 없는 규칙: quality/copy-state — 법칙으로 덮거나 성운에 올려라
```

### ⛔ 별의 관문을 세우는 파서가 파일 전체를 훑고 있었다

`bigbang/engine.mjs` 는 법칙의 `rules:` 를 **파일 전체**에서 찾았다.
법칙 본문이 그 낱말을 인용하면 **별의 관문이 엉뚱한 규칙 묶음**으로 세워질 수 있었다.

R66 이 만든 `lib/frontmatter.mjs` 로 통일했다. 법칙 본문에 가짜 `rules: [...]` 를 넣고
확인했다 — 관문은 **19개 그대로**다.

**변이 22종·27건 → 23종·28건.**

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | 통과 | 닫힌 성운 줄 변이를 시험에 박았고(exit 1 · 되돌리면 0), 법칙 본문 인용은 직접 넣어 관문이 안 흔들리는 것을 확인했다 |
| 실측 기반성 | 통과 | 네 파서를 하나씩 열어 읽는 범위를 확인했다. **안전했던 하나(observe→법칙)도 안전하다고 적었다** — 세고 나서 말한다 |
| 변경 정직성 | 통과 | 「지금은 안 터진 잠재 결함」(engine·render-facts)을 그렇게 적었다. 터진 것과 안 터진 것을 섞지 않았다 |
