# R15 — 선언을 빠뜨린 것을 잡는다

## 실행 요약

R14 가 남긴 것: `parses` 선언이 **자발적**이라 파싱하면서 안 적으면 쓰레기 시험이 아예
안 돌았다. 「선언했는가」를 기계가 묻게 했다.

`verify` 안에서 스키마를 파싱하는 자리가 있으면 `parses` 를 적어야 하고, 없으면 적으면
안 된다 — **양쪽 다** 잡는다. 뒤엣것도 중요하다: 헛선언은 시험을 헛돌게 만든다.

## 넣기 전에 쟀다 — 오탐 0

| 스테이지 | verify 안의 파싱 | 선언 |
|---|---|---|
| `s01` | 없음(소스를 텍스트로 본다) | 없음 ✅ |
| `s02` | `loadCloudFrontConfig` | 있음 ✅ |
| `s03` | `loadCloudFrontConfig` · `readDeployIntent` | 있음 ✅ |
| `s04` | 없음 | 없음 ✅ |

소스를 텍스트로만 보는 스테이지는 사적 스키마가 없어 해당 없다. 그 구분이 실제 코드와
맞아떨어져서 오탐이 0 이었다 — 규칙을 먼저 만들고 코드를 맞춘 것이 아니다.

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 집행 가능성 | A | 양방향으로 증명했다 — 선언을 떼면 exit 1, 파싱 없는 곳에 헛선언을 붙여도 exit 1, 되돌리면 exit 0 |
| 실측 기반성 | A | **넣기 전에** 스테이지 넷의 verify 를 열어 파싱 유무를 세고 오탐이 0 인 것을 확인한 뒤 넣었다 |
| 변경 정직성 | A | 한계를 시험 머리말과 커밋에 적었다 — **이름으로 찾는다.** 다른 이름의 파싱 헬퍼가 생기면 목록에 더해야 한다 |
| 일반화 | B | 이 검사는 **react-vite 플러그인 안에만** 있다. `harness-next` 의 스테이지는 같은 검사를 안 받는다 |
| 회귀 안전 | A | 플러그인 selftest 42 → 43, 나머지 전부 그대로 |

## 다음 단계

같은 검사를 `harness-next` 에도 걸거나, **코어로 올려** 모든 플러그인이 받게 한다.
지금은 플러그인마다 베껴야 하는데, 베끼는 것은 언젠가 어긋난다.
