# R32 — 문서로 못 고친 것을 구조로 고쳤다

## 실행 요약

변이 시험이 `git checkout --` 로 되돌렸고, 그래서 **만질 파일이 커밋돼 있어야만** 돌았다.
그 요구가 **다섯 번** 마찰을 냈다 — 라운드를 닫을 때마다 막히고 「커밋하고 다시」.

R26 에서 **사유를 보여 주게** 고쳤고(그건 필요했다), CONTRIBUTING 에 **「닫기 전에
커밋하라」**고 적었다. **그래도 안 없어졌다.** 문서는 마찰을 설명할 뿐 없애지 않는다.

**관문이 사람을 두 번 일하게 하면 사람은 관문을 우회하는 법부터 배운다.**
`--force` 가 습관이 되기 전에 구조를 고쳤다.

## 고친 것

원본을 **메모리에 들고 있다가 되돌린다.** 커밋 여부와 무관하고 남의 미커밋 변경도 안 날린다.
되돌림 확인도 git 상태가 아니라 **바이트**로 한다 — 「원래대로」의 기준은 **들어올 때의 내용**이다.

## 평가

| 축 | 판정 | 근거 |
|----|------|------|
| 문제 인식 | A | 다섯 번 반복된 뒤 **「문서로는 안 된다」**를 인정하고 구조를 고쳤다. 사유 표시(R26)는 필요했지만 충분하지 않았다 |
| 집행 가능성 | A | 미커밋 줄을 넣고 돌려 **exit 0 이고 그 줄이 살아남는 것**(md5 동일)을 확인했다. 요구 자체가 없어졌다 |
| 뒷정리 | A | 안 쓰게 된 `dirtyAmong` 을 걷어냈고, **CONTRIBUTING 의 낡은 안내도 지웠다** — 이제 사실이 아니다. 고치고 문서를 안 지우면 문서가 거짓말을 한다 |
| 변경 정직성 | A | 「다섯 번」을 세어 적었다. 몇 번 겪고서야 고쳤는지가 이 기록의 값이다 |
| 되돌림의 안전성 | B | 프로세스가 변이 도중 죽으면 **파일이 고쳐진 채 남는다.** git 되돌림도 같은 약점이 있었지만, 이제 「커밋돼 있으니 복구 가능」이라는 안전망마저 없다 |
