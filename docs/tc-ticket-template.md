# QA TC 티켓 표준 양식 (v1.2)

정책서 → GitHub Issue TC 티켓 → Playwright(TS) 스크립트 파이프라인 전용.

이 양식의 모든 필드는 **"이 TC가 통과했을 때, 아무것도 안 재고도 통과할 수 있는 경로가 있는가"**
라는 질문에서 역산되어 나왔다. 필드를 뺄 때는 그 질문에 다시 답할 수 있는지 확인할 것.

근거: `docs/tc-lessons.md`

## 🏷️ [QA-TC] 대분류 > 중분류 > 소분류 : 세분류

### 📋 1. 사전 조건 (Pre-conditions)

> 4개 항목 고정. 모르면 `미확인`이라 적고 비워두지 말 것 — 빈 칸은 "무관"으로 읽힌다.

- **진입 화면:** `<화면 이름>` (경로 문자열이 아니라 **이름**. 경로는 스크립트가 레지스트리에서 꺼낸다)
- **인증 컨텍스트:** `있음` / `없어야 함` / `무관` (**3값 필수.** 로그인이 있으면 안 되는 화면이 존재한다)
  - ⚠️ `무관`은 "편한 값"이 아니라 **"이 축은 안 쟀다"**는 뜻이다. 리포트에서 ⚪로 집계하고 통과 쪽에 섞지 않는다
- **기대 착지 URL:** `<의도된 최종 URL>` (리다이렉트가 정상이면 그 도착지를 적는다. 없으면 진입 화면과 동일)
- **착지 증거 요소:** `<그 화면에만 있는 요소 하나>` (**URL만으로는 404·에러 페이지도 통과한다.** 필수)
- **선행 상태와 그 위치:**
  - [ ] 필요 없음 (`goto` 한 줄로 시작 가능)
  - [ ] 필요함 — 상태 저장 위치: `URL 파라미터` / `localStorage·쿠키` / `인메모리(새로고침 시 초기화)` / `서버 데이터`
  - 필요한 선행 상태: `<예: 상점 1개 선택됨>`
- **분기 조건:** `<계정 등급·권한·잔액 등에 따라 화면이 갈리는가. 갈리면 갈래를 모두 적는다>` / `없음`

### 🧪 2. 테스트 항목 및 기대 결과 (Test Steps & Expected Results)

> - Action 1줄 = 사용자 행동 1개. Action 번호와 Expected 번호를 1:1로 대응시킨다.
> - 리스트/테이블 컬럼은 **하나의 Action 아래 컬럼 수만큼 Expected를 나눠 적는다** (한 줄에 몰지 않는다).
> - Expected는 "무엇이 보인다"가 아니라 **"무엇이 가능/불가능해지는가"**로 쓴다.
> - 구현을 단정하는 낱말(`disabled`, `readonly`) 대신 관찰 가능한 동작으로 쓴다.
> - 관측 대상은 **역할 + 정확한 이름**으로. 이름이 다른 텍스트와 겹치면 `정확히 일치`·`제목 레벨`을 명시한다.

1. **[Action]** ...

   - **[Expected]** ...

2. **[Action]** ...

   - **[Expected]** [컬럼A] ...

   - **[Expected]** [컬럼B] ...

### 🚫 3. 부정 검증 (Must Not Happen) — **최소 1줄 필수**

> 없으면 자동화 시 "항상 통과하는 스크립트"가 된다. 빈 칸 금지.
>
> **줄 수만 채우는 약한 부정은 금지한다.** "에러 토스트가 안 뜬다"는 아무 일도 안 일어나도 통과한다.
> 반드시 **"행동을 했는데도 일어나지 않았다"** 형태로 쓴다.
>
> - ⛔ 약함: `에러 메시지가 노출되지 않는다`
> - ✅ 강함: `발송 버튼을 클릭해도 발송 API 요청이 발생하지 않는다`

- **[행동]** ... → **[일어나지 않아야 할 것]** ...

### 🔢 4. 측정 기준 (Measurement Guards)

> "0건이라 통과"와 "미도달이라 0건"을 구분하기 위한 필드. 해당 없으면 `해당 없음`.

- **기대 모수:** `<이 화면에서 관측 대상이 최소 몇 개여야 하는가>` (0이면 그 결과는 무효로 간주)
- **하한이 아닌 입력값:** `<"A가 B를 따라간다" 류 명제 전용. 기본값·최솟값에서의 일치는 증거가 아니므로 하한을 벗어난 값을 지정>` / `해당 없음`
- **검증 대상 빌드:** `dev` / `프로덕션` / `무관` (에러·크래시 검증은 빌드에 따라 신호가 달라진다)
- **잰 화면의 출처:** `<브랜치> @ <커밋> [+미커밋변경]` / `_미기재_ — 어느 빌드에서 쟀는지 모른다`
  - ⚠️ **커밋 해시만으로는 부족하다.** 작업 트리가 dirty 면 **그 커밋의 화면이 아니다** —
    해시를 박으면 "그 커밋을 쟀다"는 **거짓**이 문서에 남는다
  - ⚠️ `(로컬 5000)` 처럼 포트만 적지 않는다. 그 포트에 **다른 브랜치** 서버가 떠 있으면
    그걸 재고 내 결과로 기록하게 되고, **에러 없이** 그렇게 된다
  - 기계가 못 고르면(리스너 2개·원격 주소·git 트리 아님) **고르지 말고 사람에게 넘긴다.**
    잘못 고르면 틀린 커밋을 자신 있게 박게 되는데, 그게 손으로 적는 것보다 나쁘다

### 🔭 5. 관측 위치 (Where To Observe)

> 생성될 spec 의 **대기 도구가 여기서 결정된다.** 적혀 있지 않으면 변환하는 쪽이 추측한다.
>
> | 관측 대상이 있는 곳 | 쓸 것 |
> |---|---|
> | **DOM 안** — 보인다·숨는다·값이 있다 | web-first assertion (`toBeVisible` 등) |
> | **DOM 밖** — 쿠키·네트워크 요청·수집기·외부 사건 | `expect.poll` (timeout·interval 명시) |
> | **기하 확정** — 위치·크기를 재야 한다 | 대응하는 단언이 없다. 고정 대기 + **이유 주석** |
>
> ⚠️ "보인다"와 "위치가 확정됐다"는 **다른 사건**이다.

- **관측 위치:** `DOM 안` / `DOM 밖 (<무엇을 폴링하는가>)` / `기하 확정`
- **DOM 밖이면 무엇이 바뀌기를 기다리는가:** `<예: 발송 API 요청이 발생한다>` / `해당 없음`

### 🎯 6. 셀렉터 힌트 & 상태 대비 (Selector Hints)

> 아는 만큼만 채운다. 모르면 `미확인`. 추측해서 적지 말 것.
>
> ⚠️ **요소가 항상 존재하면, 셀렉터가 정확해도 아무것도 재지 않는다.**
> "소진 배지가 보인다"는 배지가 늘 떠 있어도 통과한다.
> 그래서 **조건이 바뀌면 무엇이 달라지는가**를 함께 적는다. 조건 대비가 없는 관측은 무효로 본다.

| 대상 | 역할(role) | 이름(name) | 정확 일치 | 조건 A일 때 | 조건 B일 때 |
|---|---|---|---|---|---|
| | | | Y/N | | |

> 예: 발송 버튼 / button / 발송 / Y / `잔액>0`: 클릭 시 발송 요청 발생 / `잔액=0`: 클릭해도 요청 없음

### 💬 7. Review & Metadata

- **요구사항 ID:** `<정책서 ID. 복수면 콤마 구분>`
- **유형:** `정상` / `경계` / `오류` / `상태전이`
- **우선순위:** `High` / `Medium` / `Low`
- **테스트 타입:** (기본 Blank / Regression `R` / Edge case `E`)
- **정책서 버전:** `<vX.Y>`
- **자동화 대상 여부:** `Y` / `N` (N이면 사유 병기)
- **기대결과 확정 여부:** `확정` / `[기대] 미확정 — ※ 현 동작 병기`

## 결과 상태 모델

실행 리포트와 스크립트 내부는 **층위가 다르다. 섞지 말 것.**

| 층위 | 상태 | 규칙 |
|---|---|---|
| 수기 실행 리포트 | `Pass` / `Fail` / `Block` / `N/A` | "안 돌린 것"을 Pass로 세지 않기 위해 4상태 유지 |
| Playwright 스크립트 내부 | `Pass` / `Fail` 만 | 미도달·모수 0·하한 일치는 **skip이 아니라 throw**. 스크립트 안에 "못 쟀다" 상태를 만들면 초록으로 읽힌다 |
| 파이프라인 종료 코드 | `0` / `1` / **`3`** | TC나 spec을 **받지 못한 경우**는 실패도 통과도 아니다. 재시도 1회 후 `exit 3` |

⚠️ **집계 규칙:** `Block`·`N/A`·인증 `무관`은 **통과율 분모에서 뺀다.**
"25개 중 25개 통과"에 N/A가 섞이는 순간 그 숫자는 거짓이다. 못 잰 축은 **따로 이름을 불러** 리포트에 남긴다.

## 변환 후 필수 검증

TC → 스크립트 변환 직후, 그 스크립트를 한 번 돌려 **아직 실패하는지** 확인한다.

```
spec 생성 → 정적 관문 통과 → 그 spec을 지금 돌린다
  exit === 0  → ⛔ 거부. "처음부터 통과 = 아무것도 재지 않는다". spec 폐기
  exit !== 0  → ✅ 수용. 이후 느슨하게 고치지 못하도록 잠근다
  spec 미수령 → 재시도 1회 → 그래도 없으면 exit 3 (조용히 통과시키지 않는다)
```

에이전트가 TC도 쓰고 스크립트도 쓰면 자기 채점이다. 이 단계가 그 유일한 방벽이다.

## TC 생성물에 대한 정적 관문 (형식만 잰다)

**"내용이 옳은가"는 재지 않는다. "형식이 재고 있는가"만 잰다.** 잡히는 것:

- [ ] 사전조건 필수 필드 누락
- [ ] **부정 검증 0줄** ← 가장 값진 검사
- [ ] 부정 검증이 "행동을 했는데도" 형태가 아님 (약한 부정)
- [ ] 요구사항 ID 미매핑
- [ ] Action ↔ Expected 번호 불일치
- [ ] 착지 증거 요소 누락
- [ ] 셀렉터 힌트에 조건 대비가 없음

⛔ **못 잡는 것: 필드가 다 채워졌지만 얕은 TC.** 현재 방법으로는 잡히지 않는다.
**못 잡는다고 여기 적어 두는 것**이 지금 할 수 있는 최선이다.

## 검사를 넣은 뒤

넣은 검사는 **반드시 일부러 깨서 무는지 확인한다.** 다른 검사에 먼저 걸리면 조준이 틀린 것이다.
초록불을 증거로 삼지 않는다.
