# 결과물

**아래 출력 블록은 전부 실제 실행 출력이다.** 꾸민 예시가 아니다. 그래서 남는 질문은 「진짜인가」가 아니라
**「언제·어디서 잰 것인가」**다 — 그 구분을 흐리면 「전부 실제 출력」은 사실인 채로 **문서 전체가 거짓말**이 된다.

## 표식 셋 — 당신이 지금 다시 잴 수 있는가

| 표식 | 뜻 | 당신 기계에서 |
|---|---|---|
| ✅ **지금 상태** | 이 저장소와 픽스처만으로 난다 | **다시 잰다** |
| ⚠️ **그 기계에서만** | 좌표가 `galaxies.local/` 에 있어 커밋되지 않는다 | 그 저장소를 가진 사람만 |
| ⛔ **그때의 기록** | 잰 대상이 더는 여기 없다 | **못 잰다 — 그래도 지우지 않는다** |

## 왜 갈리나 — 은하 명부가 둘이다 (R152)

| 명부 | 무엇이 사나 | 커밋되나 |
|---|---|---|
| `galaxies/` | **상대 경로** 좌표 — 남의 기계에서도 같은 자리를 가리킨다 | ✅ 커밋된다 |
| `galaxies.local/` | **절대 경로** 좌표 — **그 기계에만 있다** | ⛔ gitignore |

⇒ **클론한 사람에게는 `galaxies.local/` 이 없다.** 진짜 은하에서 잰 §3·§4·§5 가 ⚠️ 인 이유가 이것이고, 픽스처로
재는 것은 누구나 다시 잰다. ⛔ **어느 이름이 어느 명부에 사는지는 여기 열거하지 않는다**(§9) — 이름은 사람이 정하는
것이라 열거하면 그 목록 밖은 안 보이고, 늘 때마다 한 자리만 고쳐진다. 지금 무엇이 있는지는 `universe.config.json`
의 `galaxies` 와 두 폴더가 **정본**이고, 커밋되는 쪽에 절대 경로가 섞이지 않았는지는 `universe coordinates` 가 잰다.

**게이트 7개가 전부 초록인데 마지막 줄이 빨갛다.** 이것이 「초록불인데 틀린 자리」다. 그리고 이 실행이 예산 설정
오류까지 드러냈다 — 물려받은 1,229KB 는 기준선(1,700KB)보다 낮아서 **결함을 다 고쳐도 통과할 수 없는 축**이었다.

## 3. 진짜 은하에서 2차 팽창 — 신호가 셋이 됐다 (R146)

> ⚠️ **그 기계에서만 재현된다.** 여기 나오는 `backoffice` · `whitehole` 은 남의 저장소라 좌표를 커밋하지 않고
> (`galaxies.local/`), 2026-09-08 에 `universe.config.json` 목록에서 뺐다 — 절대 경로가 공개 저장소에 올라간 사고 뒤의 규율이다(R152).

⛔ **그렇다고 아래 기록을 지우지 않는다.** 이것은 그때 진짜 저장소에서 잰 값이고, 픽스처에서는 영영 안 보였을 결함들이 여기서 나왔다 —
**기록은 역사고, 목록은 지금이다.** 지금 목록은 우주 저장소의 `galaxies/README.md` 가 **생성해서** 말한다(여기 옮겨 적으면 또 낡는다).

`backoffice`(2,027파일 · yarn 4.10.3)에서 2차 팽창을 처음 **끝까지** 걸었다. 픽스처에서는 안 보이던 결함 다섯이 여기서 보였고, 전부
**「못 쟀다」를 말할 칸이 없어서** 난 것이었다. 신호가 `ok: boolean` 하나였으므로 안 잰 축은 초록불 아니면 빨간불로 갔다.

```
── 컴파일 관문 — 빌드: `yarn build`
   ✅ 별이 은하에서 선다 (11.4초)
   ✅ 별이 이 은하의 집안 규칙을 지킨다
── 게이트
   ❌ lint error 11 · warning 130
   ⚪ build     — 못 쟀다: 앞의 게이트가 빨간불이라 돌지 않았다
   ⚪ test      — 못 쟀다: 앞의 게이트가 빨간불이라 돌지 않았다
   ⚪ typecheck — 못 쟀다: 앞의 게이트가 빨간불이라 돌지 않았다
   ⚠️ 못 잰 축 3개 — **통과가 아니다. 아무도 안 봤다는 뜻이다.**
── 빨간 축
   ❌ lint  귀속: **은하 탓 — 별의 폴더 밖** · 근거: 원본 산출
── 되돌렸다 — 지운 파일 3개 + 빈 폴더
```

**신호가 셋이다**: ✅ 잰 초록 · ❌ 잰 빨강 · ⚪ **못 쟀다.** R146 **전이었다면** 화면은 `❌ lint` 한 줄뿐이었다 —
build·test·typecheck 가 통과했는지 안 돌았는지 **가릴 수 없었다.** 없는 줄은 초록불처럼 읽힌다.

**못 한 것도 적는다.** `error 11` 은 **그 은하의 트렁크가 원래 빨간 것**이다(기준선 그대로). 별 자신의 lint error 1건은 집안 규칙
관문이 고쳤고, 자가 수정은 **옳게 거절했다** — 별의 폴더 밖 error 를 우주가 고칠 일이 아니다. ⇒ **이 은하에서 별은 여전히 게이트를 못 지난다.** 도구의 결함이 아니라 은하가 원래 빨갛다.

**남의 저장소는 들어갈 때와 같다.** 들어갈 때 미커밋 3건 · 나올 때 **같은 3건**. 탐침 별은 세 번 태우고 세 번 지웠다. 커밋하지 않았다.

## 4. 진짜 은하에서 3차 실주행 — 별을 빨갛게 만든 것은 우주 자신이었다 (R148)

> ⚠️ **그 기계에서만 재현된다**(§3 과 같은 은하).

같은 은하에서 3차 팽창을 **모델을 부르는 진짜 주행**으로 돌렸다(구독 경로 · 턴 상한 10).

```
은하 backoffice · 태양계 brandmessage · 별 BrandMessageQuotaCard
요구사항: 브랜드메시지 발송 잔여 건수를 카드로 보여 주고, 잔여가 0이면 소진 배지를 띄운다
결과: 턴 10/10 소진 · 게이트 1회 · [NOT YET] · 되돌림(파일 4개 + 빈 폴더)
```

lint 산출(원본 JSON)을 **파일별로 갈라** 세니 원인이 뒤집혔다:

| 파일 | error |
|---|---:|
| `BrandMessageQuotaCard.tsx` | **0** |
| `useBrandMessageQuotaCard.ts` | **0** |
| `index.ts` | **0** |
| `BrandMessageQuotaCard.feature.test.tsx` | **6** |
| (별 밖 — 은하의 트렁크) | 11 |

**에이전트의 구현 셋은 error 0 이다.** 빨간불은 전부 에이전트가 **추가한 테스트 파일**에서 났고, 그 파일이 빨간
이유는 이 저장소에 `vitest`·`@testing-library/react` 가 **없어서** 타입이 `any` 로 풀린 것이다.

⛔ **그 테스트 파일을 우주가 시켰다.** 같은 실행의 1차 팽창은 「이 은하는 테스트를 못 돌린다 — 만들면 빌드가 깨진다」고 말해 놓고, **200줄 뒤**
에이전트 브리핑은 「새 테스트 파일을 같이 내라」고 적고 있었다. 에이전트는 시킨 그대로 했다. **고쳤다** — 브리핑의 테스트 규칙을 1차와 **같은 값**(`canRunTests`)으로 가른다.

**턴 예산이 진짜 은하에서 어떻게 쓰이는가** (픽스처에선 안 보이던 벽):

| 턴 | 무엇 |
|---|---|
| 1–7 | **probe** — 자매 별의 관례 · 배지 컴포넌트 · 시맨틱 토큰 · 테스트 관례 |
| 8 | patch (관문 통과 · 파일 4개) |
| 9 | submit → 게이트 |
| 10 | submit (바이트 그대로라 게이트 안 돎) — 예산 소진 |

**10턴 중 7턴이 조사다.** 그래서 게이트가 빨간불을 돌려준 뒤 **고칠 턴이 0** 이었다. 조사와 수정이 한 예산을 나눠 쓰는 것이 옳은지는 성운에 올렸다.

**남의 저장소는 여기서도 들어갈 때와 같다**(3건 → 같은 3건). 커밋하지 않았다.

## 5. 주행 전 — 판정이 넷이 됐다 (R149)

> ⚠️ 아래 **출력**은 그 기계에서만 난다. ✅ 그 아래 **판정 넷의 갈림**은 지금 코드의 동작이다.

「못 쟀다」는 정직하지만 **너무 늦다.** `backoffice` 의 `.yarnrc.yml` 은 `${NODE_AUTH_TOKEN}` 을 참조해서, 그 변수가
없으면 yarn 이 **어떤 명령도 안 돈다** — 그런데도 3차라면 모델을 턴 수만큼 부른 뒤에야 그것을 알았다. 그래서 **주행 전에** 본다.

```
⛔ **은하 backoffice 가 서지 않는다** — 좌표가 요구한 환경변수 1개가 비어 있다:
     · NODE_AUTH_TOKEN
   이것은 「못 쟀다」가 아니다 — **재기 시작할 수도 없다는 뜻**이다.
   ⛔ 그래서 여기서 멈춘다 — 못 잴 것이 뻔한 곳에 별을 쓰거나 모델을 부르지 않는다.
⇒ 남의 저장소에 파일 0개. exit 2.
```

| 언제 아나 | 무엇이라 말하나 |
|---|---|
| **주행 전** — 은하가 선언한 필수 환경변수가 없다 | ⛔ **은하가 서지 않는다** (R149) |
| 주행 중 — 명령을 선언 안 했거나 앞이 막혔다 | ⚪ 못 쟀다 (R146) |
| 주행 중 — 도구가 돌았고 빨간불 | ❌ 별 탓 / 은하 탓 (귀속) |
| 주행 중 — 도구가 돌았고 초록불 | ✅ 잰 초록 |

⛔ **변수 이름을 우주가 열거하지 않는다** — 무엇이 필요한지는 **은하가 선언한다**(`requiredEnv`).
선언 안 한 은하에는 아무 영향이 없다. **값은 읽지 않는다** — 있는지만 본다.

## 6. 빅뱅 — 태어난 별

> ⛔ 태어난 별의 출력은 **그때의 기록이다**(그 은하가 여기 없다). ✅ 그 아래 **음성 시험**은 지금 상태다 — 템플릿에 위반을 심으면 지금도 문다.

```
💥 빅뱅 — 실측 은하 A · 태양계 dashboard · 별 DashboardToday
   자리: apps/web/src/components/pages/alimtalk/dashboard/DashboardToday

   + DashboardToday.test.tsx  (23줄)
   + DashboardToday.tsx       (42줄)
   + index.ts                 ( 4줄)
   + useDashboardToday.ts     (33줄)

── 관문 — 은하가 켠 법칙 5개 · 규칙 17개        ← 그때의 출력이다(지금은 다르다)
   ✅ 태어난 별이 법칙을 지킨다.
```

**관문이 무는 것을 음성 시험으로 증명했다.** 템플릿에 일부러 위반을 심었더니:

```

        <div ⏎               onClick=
        → 클릭 가능한 것은 `<button type="button">` 이다.
   ❌ [tailwind/arbitrary-value] BadStar.tsx:24  gap-[16px]
   ❌ [tailwind/arbitrary-value] BadStar.tsx:24  bg-[#FFFFFF]
   ❌ [tailwind/theme-hardcoded]  BadStar.tsx:24
   ❌ [repo/arrow-only]           BadStar.tsx:7

⛔ 별이 태어나지 않았다 — 템플릿이 법칙을 어긴다(위반 5건).
```

**exit 1 · 파일을 쓰지 않는다.** 원복 후 exit 0.

## 7. 우주 자신의 검사

> ✅ **지금 상태다.** 이 저장소만 있으면 `universe check` 가 그대로 낸다.

```
── 중력 법칙 — 모든 문서는 parent 또는 related 를 갖는다
── 보존 법칙 — 별(소스 산출물)은 우주 안에 두지 않는다
── 관측 법칙 — 모든 법칙에 「재는 법」이 있고, 그 안에 돌릴 명령이 있다
── 관측 법칙 — 검사 명령을 파이프에 물려 판정하지 않는다 (경고만)
── frontmatter 필수 필드 (name·title·type·description)
── 물질 법칙은 applies_to 와 rules 를 갖는다
── config 정합 — laws · forces · orbits 배열 ↔ 파일

✅ 우주가 자기 법칙을 지킨다.
```

첫 실행에서 **우주 자신의 위반 2건**을 잡았고, 모델링 오류 1건(기관의 부모를 잘못 지정)도 검사가 드러냈다.

이것은 관문 **하나**다. 전체 수는 위 「지금 상태」 표가 **생성해서** 말한다(목록은 `lib/gates.mjs` 한 자리에 있다 —
수는 는다). `universe check` 가 전부 돌린다. 이 자리엔 「지금 25개」라고 손으로 적혀 있었고 실제로는 26개였다 —
그래서 생성으로 옮겼다(R161). 가장 최근에 든 둘은 **좌표 감사**(R152) · **3차 배선**(R147)이다.

### 한 바퀴가 얼마나 걸리는가 — 재고 나서 CI 를 세웠다 (R154)

```
관문 25개 합계 ~53초 · 그중 `검사가 무는가` 하나가 39.7초(75%)
나머지 24개는 전부 4초 이하 — 빌드를 돌리는 것들조차(광속 한계 1.2초 · 3차 배선 3.8초)
엔진 빌드는 2초
```

⇒ **나누지 않았다.** 계획은 「빠른 것/느린 것으로 가른다」였는데 실측이 그 전제를 뒤집었다 — 나눌 것이 없고, 무거운 것
하나가 **가장 값진 것**(변이 시험)이라 뺄 수도 없다. `.github/workflows/check.yml` 이 PR 과 `main` 에서
**`node bin/check.mjs` 한 판**을 돌린다(node 22).

**CI 는 개수를 세지 않는다** — 관문은 `lib/gates.mjs` 에서만 늘고, CI 는 그 파일이 낸 것을 전부 돌린다. ⚠️ 다만
워크플로의 **단계 이름**에는 아직 그때의 수가 손으로 박혀 있다. 이름은 아무것도 막지 않지만 읽는 사람에게는
거짓말이고, 문서에 그 수를 옮겨 적는 것은 `universe parts` 가 **막는다**(손으로 적은 「관문/명령 N개」 자리를 센다).

**CI 는 첫 주행에서 혼자서는 못 볼 결함 둘을 잡았다.** 로컬은 그때 전부 초록불이었는데(R154), 둘 다 **내 기계에만
있는 것** 때문이었다: 폴더 구조 그림이 gitignore 된 `galaxies.local/` 을 그리고 있었고(깨끗한 클론에선 영영
「낡았다」), 커밋 관문 검사가 **커밋을 안 하는 CI** 를 developer 기계로 알고 빨간불을 냈다.

## 8. 발행 — GitHub 위키 7페이지

> ✅ **지금 상태다** — 단, 네트워크가 있고 위키가 한 번은 만들어져 있어야 한다.

전파 대상이 **git 위키**다(R151 · `beacon/wiki.mjs`). Confluence 로 보내던 때와 달라진 것:

| 전(Confluence) | 지금(GitHub 위키) |
|---|---|
| 사이트·스페이스 키·**페이지 id 일곱**이 커밋돼 있었다 | **적을 좌표가 없다** — 주소를 `origin` 에서 파생한다 |
| 본문이 MCP 로만 읽혀 대조 검사가 **혼자 못 돌았다** | 스스로 `clone` 해서 **바이트로** 대조한다 |
| 왕복이 글자를 바꿔 **정규화 여섯 패턴**이 필요했다 | **통째로 없어졌다** — git 은 바이트를 그대로 든다(7장 전부 정규화 없이 동일) |

```
Universe (개요 · 다섯 층 · 무엇이 배달되고 무엇이 안 되나)
├── 법칙 (Laws)            메타 4 + 물질 6 · 규칙 id · 「관측 법칙이 자란 자리」 · 추가 절차
├── 힘 (Forces)            종류 3 + 관측자 + 발견 카탈로그
├── 관측소 (Observatory)   다섯 장치 · 엔진 · 지켜야 할 것 · 관문이 먼저인 이유
├── 은하 (Galaxies)        등록법 + 좌표 스키마
├── 성운 (Nebula)          형식 + 「0건은 무죄가 아니다」
└── 라운드 (Rounds)        평가 규칙 + 이력 + 성숙도
```

대조 검사를 **양방향으로** 쟀다: 같으면 통과(7장) · 위키를 손으로 고치면 문다(exit 1) ·
위키가 없으면 **「못 쟀다」로 exit 0**(실패가 아니다) · GitHub 아닌 origin 이면 주소를 지어내지 않는다.

⛔ **그래도 관문에는 아직 없다.** 사유가 바뀌었을 뿐이다 — 이제는 **네트워크가 필요하고 위키가 한 번은 만들어져
있어야 해서**다. 갓 클론한 우주·오프라인 CI 에서는 「못 쟀다」로 지나가므로, 넣으면 **재는 척만 하게 된다.** 낡은
사유를 그대로 두는 것도 결함이라 여기 적어 둔다. 렌더러는 사실을 쓰지 않는다 — 우주의 실제 파일을 읽어 조립한다.
**그래서 낡을 수 없다.**
