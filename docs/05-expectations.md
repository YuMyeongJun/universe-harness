# 결과 예측

> **"명령어 한 번으로 서비스가 나오는 마법"은 아직 없다.** 그 마법에 가는 길이 있을 뿐이다.

이 문서는 부풀리지 않는다. 아래 수치는 전부 실측이거나 **미측정이라고 표시**돼 있다.

---

## 도입 첫날 — 확실한 것

### 즉시 드러나는 것: 아무도 안 보던 위반

실측 은하(파일 1,227개)에서:

| 법칙 | 위반 | 기존 게이트가 잡나 |
|------|-----:|-------------------|
| 토큰 | 651 | ❌ tailwind 관련은 prettier 정렬 플러그인뿐 |
| 평탄성 | 159 | ❌ `no-nested-ternary` 설정 없음 |
| 네이밍 | 85 | ❌ `naming-convention` 설정 없음 |
| **접근성** | **59** | ❌ **`eslint-plugin-jsx-a11y` 미설치** |
| **합계** | **954** | |

**「기존 게이트가 잡나」는 설정 파일을 직접 열어 확인한 것**이다. 즉 954건은
빌드·린트·테스트가 전부 초록인 채로 통과하고 있었다.

⚠️ **이 수는 은하마다 다르다.** 당신 저장소에서 직접 재라 — `universe observe`.
0건이 나올 수도 있다(그러면 이 우주가 필요 없다는 뜻이고, 그것도 정당한 결과다).

### 즉시 서는 것: 회귀 방어선

기준선을 심으면 **위반 수가 늘어날 때 관측소가 막는다.**
이미 있는 954건을 오늘 다 고칠 필요는 없다 — **더 늘지 않게 하는 것**이 첫 성과다.

### 별 하나당 절약

빅뱅이 만드는 파일 4개는 **법칙을 지킨 상태로 태어난다.**
같은 것을 손으로 쓰면 토큰·시맨틱·네이밍에서 위반이 섞여 들어가고, 리뷰가 그걸 잡는다.

⚠️ **절약량은 미측정이다.** 별을 몇 개 태워 보고 리뷰 지적 수를 세야 안다.

---

## 도입 후 몇 주 — 조건부인 것

### 위반 수가 줄어드는가

**줄어들려면 「성운→법칙→별」 궤도가 실제로 돌아야 한다.**
법칙을 만들어 두기만 하면 수는 안 줄어든다 — 한 바퀴의 끝은 **기준선이 내려갔을 때**다.

### 리뷰가 가벼워지는가

관문이 잡는 것(이름·중첩·토큰·시맨틱)은 리뷰에서 빠진다.
**대신 리뷰는 관문이 못 보는 것에 집중해야 한다** — 설계·경계·도메인 정확성.

⚠️ 관문이 리뷰를 대체한다고 기대하지 마라. **관문은 기계가 셀 수 있는 것만** 본다.

## 아직 안 되는 것 — 정직하게

| | 상태 |
|---|---|
| **1차 팽창** — 법칙을 지키는 뼈대 + 관문 | ✅ **진짜 은하에서 실측했다**(R90) — 파일 1404개 저장소에서 **16초**, 그중 컴파일 관문이 그 은하의 진짜 `yarn build`(`tsc && vite build`)를 돌려 **9.4초**에 통과했고, 집안 규칙 관문이 그 은하의 진짜 eslint 로 **error 1건을 잡아 `lintFix` 로 고쳤다.** ⚠️ 관문이 별을 정말 보는지도 확인했다 — 별에 타입 오류를 심으면 `exit=2` 로 **그 파일을 짚는다.** 은하가 명령을 선언하지 않으면 **못 쟀다고 말한다** |
| **소비 팀이 실제로 얻는 것** | ✅ **실측했다**(R93) — 파일 1407개 진짜 은하에서 `universe observe` 가 **0초**에 위반 **589건**을 짚는다(토큰 56 · 시맨틱 140 · 네이밍 443 · 평탄성 5 · 응집 1). 관문은 19개 중 **8개**를 받는다 — 나머지는 우주 자신의 소스를 읽는 검사라 「여기선 못 잰다」고 말한다 |
| **위반을 고칠 수 있는가** | ✅ `observe --law <법칙> --sample N` 이 **자리(파일:줄) · 코드 · 처방**을 함께 준다. ⚠️ 처방은 오래 화면에 안 왔다 — 데이터는 규칙마다 강제돼 있는데(처방 감사 관문) 표본이 안 실어 보냈다(R94) |
| **무발동 규칙이 무죄인지** | ✅ **갈라 준다**(R93) — 그 은하에서 13개 중 3개가 침묵했고, 손으로 known-positive 를 심으니 **셋 다 발동**했다(침묵은 무죄였다). 팀마다 손으로 할 수 없으므로 `universe proven` 이 **발동 증명 명부를 생성**해 배달한다. 명부에 없는 규칙이 침묵하면 그때는 **모른다고 말한다** |
| **끊었을 때 치우는가** | ✅ `SIGINT`·`SIGTERM` 에 샌드박스를 치우고 **신호를 삼키지 않는다**(exit 130/143) — R100. ⚠️ **`SIGKILL` 은 못 잡는다**(잡을 수 있는 신호가 아니다). 라이브러리가 `process.on` 을 거는 것이 싫으면 `cleanupOnSignal: false` |
| **끊었을 때 반쯤 만든 것** | ✅ 별을 낳다 끊기면 **지우고 왜 지우는지 말한다**(exit 130) — 관문을 한 번도 안 돈 별이 「다 된 별」로 남던 자리다(R101). 잔해를 보려면 `universe new … --keep-on-fail` |
| **인용한 수치를 다시 잴 수 있는가** | ⛔ **셋은 못 잰다**(R103) — 실측 은하 A(1,227) · B(3,058) · 모노레포 은하(977). 저장소가 사라졌거나 대상에서 빠졌다. **판단은 유효하지만 수치는 그때의 기록**이다. `universe corpora` 가 새 인용을 판단 없이 못 들어오게 한다 |
| **모노레포** | ✅ **매 바퀴 재현된다**(R125) — 관문이 워크스페이스 둘짜리 저장소를 만들어 밟는다: 후보를 보여 주되 **고르지 않고**, 사람이 고른 뒤 **앱 하나만 재고**(`packages/ui` 는 안 본다) 별도 그 앱 안에 태어난다. ⚠️ 예전 근거(977파일)는 **저장소가 사라져 재현 불가**였다(R103) — 그래서 만들어서 다시 쟀다 |
| **`.ts`·`.tsx` 밖의 UI** | ⛔ **일부 못 읽는다.** Vue·Svelte·Astro 는 **문법이 달라 계속 못 읽는다**(닫아 둔 이유를 코드에 적어 뒀다). ⭐ `.js`·`.jsx`·`.mjs`·`.cjs` 는 **열었다**(R163) — 규칙이 전부 정규식이고 `.jsx` 가 `.tsx` 와 같은 6개를 발동해서다. ⚠️ **오탐 위험은 아직 안 쟀다** — 이 저장소 자신의 `.js` 48개에서 65건(매직넘버 46)이 나왔고, 그건 **대체 측정이지 판단이 아니다**. `universe init` 이 깔면서 그 비율을 말하고, 은하가 `blindJudged` 로 판단하기 전에는 `universe observe` 가 초록불을 주지 않는다 (§「우주가 못 읽는 것」). ⭐ **이제 그 비율을 저장소마다 잰다**(R163 · `universe census`) — 분모와 함께 낸다. 실측(진짜 모노레포 1곳): **1,347/1,349 (99.9%) 를 읽고 못 읽는 것은 `.mjs` 2개(0.1%)**. ⚠️ **처음엔 59개(4.2%)로 나왔다** — 그중 **57개가 gitignore 된 일회용 QA 프로브**였다. 옆 저장소 세션이 자기 저장소에서 다시 재서 잡아 줬다. ⛔ **「모수가 다르다」가 아니라 「한쪽은 **버려질 것**을 센다」**가 정확한 진술이다 — 스크래치가 분모에 들어오면 **프로브를 하나 만들면 늘고 지우면 준다.** 코드 품질과 무관하게 기준선이 흔들린다. ⇒ **git 이 무시하는 것을 묻는 축**을 넣었다(`git ls-files` 로 한 번에 받는다). **뺀 것도 화면에 수로 말한다.** ⚠️ 여는 순서는 **`.mjs`/`.js` 를 `.vue`/`.svelte` 보다 먼저** — 파서가 같아 싸고, 그 저장소의 **자체 검사 도구**가 거기 산다(도구의 결함은 도구를 읽어야 보인다). ⛔ `.vue`·`.svelte` 우선순위는 **표본이 없어 「모른다」**로 둔다 |
| **은하가 서는가** — 재기 전에 먼저 본다 | ✅ **R149**. 좌표가 `requiredEnv` 를 선언하면 별을 쓰기도 모델을 부르기도 **전에** 훑고, 비면 「**은하가 서지 않는다**」로 멈춘다(옵트인 · 값은 안 읽는다). ⚠️ 이것은 ⚪ 「못 쟀다」의 다른 이름이 **아니다** — 판정이 넷이 됐다: **주행 전 · 은하가 안 선다** / 주행 중 · ⚪ 못 쟀다 / 주행 중 · ❌ 별 탓 / ❌ 은하 탓. ⛔ 실측 근거(R148): `NODE_AUTH_TOKEN` 이 없으면 yarn 이 **어떤 명령도 안 돌아** 게이트가 통째로 깨지는데, 그 상태로 3차를 태우면 **모델을 턴 수만큼 부르고** 에이전트가 못 고치는 것을 고치려 든다. 「못 쟀다」는 정직하지만 **너무 늦다** — 못 잴 것이 뻔한 곳에 사용량을 쓴다 |
| **2차 팽창** — 태어난 별에 게이트까지 자동으로 돌고 빨간 축을 스스로 고침 | ✅ **진짜 은하로 걸었다**(R146 · backoffice 2,027파일 · yarn). 컴파일 관문 11.4초 통과 · 집안 규칙 관문이 별의 lint error 1건을 고침 · 게이트가 은하의 트렁크 error 11건에 막히자 **「은하 탓 — 별의 폴더 밖」으로 옳게 귀속**하고 자가 수정을 거절 · 되돌리기가 흔적 0. ⚠️ **별은 이 은하에서 게이트를 못 지난다** — 도구가 아니라 **은하 트렁크가 원래 빨갛다**. 그 벽은 아직 안 치웠다. ⚠️ 이 주행이 결함 다섯을 잡았다 — 전부 **「못 쟀다」를 말할 칸이 없어서** 생긴 것이다(선언 안 한 `test` 를 지어내 `✅ exit 0` · `commands.typecheck` 를 R45 부터 아무도 안 읽음 · 앞이 막혀 안 돈 축이 화면에서 사라짐 · `yarn` 이 컴파일 전에 죽은 것을 「별이 서지 않는다」로 귀속 · 되돌리기가 자기 `lintFix` 를 남의 작업으로 착각해 **남의 저장소에 파일을 남김**). 이제 신호에 셋째 칸(`unmeasured`)이 있고 ⚪ 로 말한다. ⚠️ **예전에 여기 적힌 「2차의 자가 수정은 에이전트 주행이라 아직」은 틀렸다** — 2차의 자가 수정은 은하의 `lintFix` 명령 하나뿐이고 **모델을 안 부른다**(R146 주행의 모델 호출 0회). 에이전트가 도는 것은 3차다. 그리고 그것도 **「유료」가 아니다**(R140·R145 실측) — 엔진은 `claude -p` **CLI 를 부르고**, 자식 env 에서 `ANTHROPIC_API_KEY` 를 지운다. 키가 없으면 **그 기계의 Claude Code 구독**으로 돈다 |
| **3차 팽창** — 요구사항 한 줄 → 도는 화면 | ✅ 실측 2회(최근 R145: 턴 7 · 게이트 1 · exit 0 · 궤적에 `nebula-end`·`requirement-signal` 둘 다). ⛔ **구독 경로로 돈다** — 가짜 `ANTHROPIC_API_KEY` 를 넣고 완주하는 것으로 반증했다(키가 자식에 갔다면 인증 실패로 죽는다). ⚠️ **이 보증이 왜 필요한가 — 야생의 반례를 읽었다**(R149 · 같은 기계의 다른 저장소, 이름은 적지 않는다). 거기도 「구독으로 돌려 API 과금을 피한다」가 그 모드의 존재 이유인데, `claude` 를 띄우며 `{ ...process.env }` 를 그대로 넘기고 **중첩 세션 변수 셋만 지운다** — `ANTHROPIC_API_KEY` 는 안 지운다. ⇒ 운영자 셸에 키가 있으면 **구독이 아니라 API 로 청구되면서 화면은 똑같이 잘 돈다.** 아무도 모른다. 몰라서가 아니라 **물려 본 것만 열거해 지웠기 때문**이다(§9 의 그 형태). ⇒ 키 격리는 **목구멍 하나**(`claudeCli`)로 모으고 **가짜 키로 태워 반증**해야 서는 종류의 보증이다. ⚠️ **충족은 여전히 못 잰다** — 게이트가 재는 건 lint·build·test 다. 그리고 3차가 만든 기능엔 테스트가 안 생긴다 . ⇒ **미충족은 잰다**(R130): 요구사항의 알맹이 낱말이 코드에 하나도 없으면 말한다. **조용해도 충족이 아니고, 시끄러우면 확실히 안 한 것**이다 — 한쪽만 재는 신호다. ⚠️ **한국어에서만 돈다**(R131) — 영어는 알맹이와 기능어를 가를 손잡이가 없어 **「못 쟀다」고 말한다**|
| **에이전트가 스테이지를 푸는 비율** | 🟡 **첫 SOLVED 실측** — `s04` 1회 성공(reward 0.81). **네 스테이지 전부 재현된다**(양방향 확인). 다만 1회는 비율이 아니다 — 나머지 셋은 오라클로만 풀었다 |
| **궤적 → 지식 카드 수율** | 🟡 **실측 8장 → 4장** (재는 법 없음 2 · 없는 경로 1 · id 형태 위반 1) |
| 다른 스택(Next.js) | 🟡 `@plugins/harness-next` 있음 — 스테이지 1개(`use client` 경계). **진짜 Next 저장소로는 미검증**. ⚠️ 다만 R129 가 작은 Next 저장소를 만들어 밟아 **좌표 초안이 `app/` 을 못 보던 결함**을 찾아 고쳤다 — 「미검증」이 「아무것도 못 잰다」는 뜻은 아니었다 |
| **명령을 외워야 하는가** | 🟡 **가른 것은 실측, 쓸 만한가는 못 쟀다**(R161). 인자 없이 `universe` 를 치면 **사람이 치는 명령만** 보이고(나머지는 `universe check` 가 알아서 부른다 — ⛔ 몇 개인지는 여기 안 적는다. 「10개 / 22개」라고 적어 뒀다가 낡았다), 고른 것에 필요한 것만 묻고 **만들어진 명령줄을 찍고 나서** 실행한다 — 다음엔 메뉴를 안 거치게 되는 것이 목표다. ⛔ 화면은 **관문을 못 끈다**(「무시하고 계속」 갈래가 없고, 그 갈래가 생기는지를 변이로 문다). ⚠️ **실제 터미널에서 사람이 끝까지 써 본 표본이 없다** — 대본으로만 몰았다. 「쓸 만한가」는 **못 쟀다**(§8) |
| **도구가 못 부를 이름을 가르치지 않는가** | ✅ **실측 사건에서 고쳤다**(R161). 도움말과 메뉴가 `universe …` 라고 가르치는데 그 이름이 기계에 없어 `command not found` 가 났다 — 문서는 `node <저장소>/bin/universe.mjs` 라 하고 있었다. **두 말이 달랐다.** 이제 PATH 에서 찾은 것이 **이 패키지의 그것일 때만** `universe` 라 하고, 아니면 도는 형태를 말하며 잇는 법(`npm link`)까지 알려 준다. ⚠️ 남의 `universe`(npm 의 crossfilter/universe)가 PATH 에 있어도 그것을 가르치지 않는다 |
| **우주 안에 우주가 깔리는가** | ✅ **막는다**(R161) — `universe init` 은 우주 저장소 안에서 **거절한다**(경고가 아니다 · `--force` 로도 안 뚫린다 · 파일을 만들기 전에 선다). ⚠️ 하루에 **세 번** 났던 사고다. ⛔ 진짜 값은 더러운 워킹트리가 아니라 **복제된 문서가 참조를 하나 더 만들어 변이 하나가 안 물게 된 것**이다 — 더러운 트리는 보이지만 **죽은 검사는 안 보인다.** `--dir` 로 자리를 대면 통과한다(명시한 것은 일부러다) |
| 다른 스택(Vue) | ⬜ 플러그인 필요 |

### 첫 SOLVED — 그리고 그것이 드러낸 것

엔진에는 샌드박스에 결함을 심고 에이전트가 고치게 하는 스테이지가 넷 있다.
오래 SOLVED 가 하나도 없었는데, **문제는 에이전트가 아니라 은하였다.**

기존 4회는 **전부 `s01`** 이었고, `s01` 은 주입 코드가 특정 저장소의 의존성 목록을
하드코딩하고 있어 다른 저장소에서는 **boot build 부터 깨진다.** 즉 넷 중 어느 것이
이 저장소에서 도는지 한 번도 확인하지 않은 채 **안 도는 것만 4번 돌린 것이다.**

전용 픽스처 은하(`fixtures/tiny-galaxy` · React 18 + Vite 6 + Vitest 3 + ESLint 9,
게이트 한 바퀴 **3.5–4.2초**)를 세우고 넷을 전부 `reset()` 시켜 갈랐다:

| 스테이지 | 처음 갈랐을 때 | **고친 뒤 (양방향 실측)** |
|---|---|---|
| `s01` 번들 꼬임 | ❌ boot build exit 1 — 주입 코드가 특정 저장소 의존성을 하드코딩 | ✅ 결함 `FAILED 0.78` → 오라클 `SOLVED 0.96` |
| `s02` SPA 딥링크 | ✅ 돈다 | ✅ 회귀 없음 |
| `s03` 캐시 무효화 | ❌ 제출 시 프로세스 크래시(ENOENT) | ✅ 결함 `FAILED 0.751` → 오라클 `SOLVED 0.96` |
| **`s04` 토스 품질** | ✅ 돈다 | ✅ **에이전트 1회 `SOLVED 0.81`** |

**넷 다 재현된다.** 「결함 상태에서 ❌ · 고친 상태에서 ✅」를 **양쪽 다** 확인했다 —
한쪽만 보면 「항상 통과」와 「항상 실패」를 못 가른다.

두 스테이지가 못 돌던 원인은 서로 달랐다:

| | 원인 | 왜 안 보였나 |
|---|---|---|
| `s01` | 결함 주입이 **특정 저장소의 의존성 목록을 하드코딩**했다. 그것들이 없는 은하에선 주입 자체가 빌드를 깬다 | 그 저장소에서만 돌려 봤다 |
| `s03` | **스테이지가 자기 결함으로 삼는 파일을 스스로 안 만들었다.** `setup()` 은 CloudFront 형상만 심고 워크플로는 안 심었는데 `verify()` 가 `catch` 없이 그것을 읽었다 | `simulateDelivery` 는 같은 호출을 `.catch` 하는데 **스테이지만 대칭이 깨져** 있었다 |

`s04` 를 **진짜 에이전트로 1회** 돌린 궤적(`.harness/trajectories/s04-…-70117-24541.jsonl`):

```
probe×4 → patch(REJECTED: repo/braces-required 2건) → patch(ALLOWED) → submit
SOLVED · reward 0.81
```

검산: `0.4×1 + 0.4×1 + (0.2 − 0.05×1) − 0.02×7 = 0.81`. 게이트 3 · 채점 6 전부 초록.
**이 프로젝트 최초의 SOLVED 다.** 반려를 받고 스스로 고쳐 다시 낸 것까지 궤적에 남았다.

⚠️ **1회를 성공률로 말하지 않는다.** `s01`·`s03` 은 여전히 SOLVED 0 이고, `s02` 는
오라클로만 풀었다(에이전트 미주행). 비용은 LLM 8회였다.

### 이 한 번이 엔진 결함 둘을 잡았다

| 결함 | 무슨 일이 | 고침 |
|---|---|---|
| **boot build 실패를 삼켰다** | `s01` 이 `exit 1` 인데 브리핑은 「게이트는 전부 초록불이다」라고 말하고 **LLM 을 14번 태웠다.** 종료코드는 궤적에 **이미 있었는데** 아무도 안 봤다 | `reset()` 이 그 자리에서 멈춘다. 실측: 14회 → **0회** |
| **채점 예외가 궤적을 날렸다** | `s03` 의 `ENOENT` 가 프로세스를 죽여 궤적 파일이 안 써지고 샌드박스가 누수됐다 | `stage.verify()` 를 `try` 로 감싸고 **터진 채점을 빨간 신호로** 기록한다 |

앞의 것은 관측 법칙 §3(종료코드를 읽어라)을 **엔진이** 어긴 사례다.

## 우주가 못 읽는 것 — 실측으로 정한 경계

규칙은 `.ts`·`.tsx`·`.js`·`.jsx`·`.mjs`·`.cjs` 를 읽는다. **넓힐지 말지는 재서 정했고, 아래가 그 기록이다** —
⛔ 결론만 읽지 마라. 「왜 그때는 안 열었고 지금은 열었나」가 이 절의 내용이다.

저장소 12곳(우주·whitehole 제외)의 파일을 세고, 못 읽는 것을 갈라 봤다.

| 갈래 | 개수 | 무엇인가 |
|------|-----:|----------|
| 생성물·정적자산 | 243 | `storybook-static/` · `dist/` · `public/` 의 번들·벤더 스크립트 |
| **진짜 못 읽는 코드** | **180** | 아래 참고 |
| 빌드 스크립트 | 26 | `scripts/*.mjs` |
| 설정 | 19 | `*.config.js` · `.eslintrc*` |

그 180개를 다시 갈라 보면:

| 무엇 | 개수 | 판단 |
|------|-----:|------|
| `.vue` (한 저장소) | 95 | **진짜 UI 다.** 넓히려면 템플릿 문법을 아는 규칙이 필요하다 — 별도 결정 |
| Node 백엔드 `.js`·`.mjs` (두 저장소) | 68 | 프론트엔드 규칙의 대상이 아니다 |
| 도구·릴리스 산출물 | 17 | `.yarn/releases/*.cjs` 같은 것 |

⇒ 그때는 **`.js`·`.jsx` 로 넓히지 않았다.** 저장소 12곳에서 **`.js`·`.jsx` 로 쓰인 UI 코드가 0개**였고,
넓히면 얻는 것 없이 번들·벤더 스크립트에서 오탐만 늘기 때문이다 —
헛도는 관문은 사람에게 **무시하는 법부터 가르친다.**

### ⭐ 그 뒤 열었다 — 그리고 **왜 열 수 있었는지**가 중요하다 (R163)

`.js`·`.jsx` 를 **열었다.** 판단이 뒤집힌 게 아니라 **재는 대상이 달라졌다**:
위 12곳은 「남의 프론트엔드」였고, 지금 우주가 **자기 자신**과 **자체 QA 도구**를 잰다.
그쪽 코드는 `.mjs`·`.js` 로 쓰여 있다. ⛔ **도구의 결함은 도구를 읽어야 보인다.**

열어도 되는 근거는 「그래 보인다」가 아니라 실측이다:
규칙 20개가 **전부 정규식**이고, `.jsx` 는 `.tsx` 와 **같은 6개 규칙이 발동한다.**
문법이 다른 `.vue`·`.svelte`·`.astro` 와는 경우가 다르다 — ⛔ **그쪽은 계속 닫아 둔다.**
「읽는다고 말하면서 못 읽는」 상태는 **못 읽는다고 말하는 것보다 나쁘다**(분모에서 빠진다).

⚠️⚠️ **그 대신 오탐 위험이 생겼다 — 이제 쟀다. 그리고 세는 자리를 같이 적는다.**

    # 무엇을 세었는가 — 이 줄이 없으면 아래 수는 아무 뜻이 없다
    node observatory/observe.mjs --galaxy <우주 자신>   # codeDirs: ["lib","observatory","bin"]

| 법칙 | 건수 | 판단 |
|------|-----:|------|
| 네이밍 | **119** | `quality/magic-number` **86** · `quality/naming-intent` 33 |
| 평탄성 | 2 | |
| 응집 | 1 | |
| 토큰(tailwind)·시맨틱(a11y) | **안 켰다** | ⛔ 이 은하엔 **화면이 없다.** 켜 봤더니 42건이 나왔는데 규칙이 **자기 예시 문자열을 문 것**이었다 |

⇒ 의심은 **맞았다.** `magic-number` 86건은 도구 코드의 `n / 100`·`slice(0, 16)` 류다.
⛔ 그러니 `.mjs`·`.js` 가 많은 은하를 **처음 등록할 때**는 기준선을 심기 전에
   `quality/magic-number` 가 낸 것부터 **눈으로 봐라.** 한 번 심으면 그 수가 「정상」이 된다.
⚠️ 그리고 **UI 없는 은하에 UI 법칙을 켜지 마라** — 규칙 파일을 읽고 위반이라 부른다.

### ⛔ 이 수를 얻기까지 두 번 헛디뎠다 — 둘 다 「분모」였다

**① 받은 수를 못 썼다.** 「이 저장소 `.js` **48개**에 65건」이라는 보고를 받았는데 재현이 안 됐다
(`git ls-files '*.js' '*.jsx'` → **4개**). 나중에 세는 줄을 받아 보니 **`lib`+`observatory` 의
`.mjs` 50개**였고, **`.js` 는 한 개도 없었다.** 수는 맞았고 **라벨이 틀렸다** —
`.js` 를 여는 판에서 「JS 48개」라고 쓰면 읽는 사람은 **`.js` 를 48개 쟀다**고 읽는다.
⇒ **수를 넘길 땐 세는 줄을 같이 준다.** 그 한 줄이 있으면 1초면 재현된다.

**② 재려다 도구가 0개를 봤다.** 훑개가 `<appDir>/src` 만 훑는데 이 저장소의 도구 코드는
`lib/`·`observatory/`·`bin/` 에 있다. 화면은 「토큰 0건 · 시맨틱 0건」이었다 —
**깨끗한 저장소와 글자 하나 다르지 않았다.** ⇒ 지금은 0개를 보면 ⚪ **못 쟀다**(종료코드 3)라고
말하고, 은하가 `codeDirs` 로 훑을 곳을 정한다(`galaxies/README.md`).

⚠️ 이 갈래 나누기는 `lib/blind.mjs` 에 있고 `universe parts` 가 실측 경로로 시험한다.
**모르는 자리는 「코드」로 떨어진다** — 실명 쪽이 아니라 경고 쪽으로 틀리게 해 놨다.

그래서 `commands.typecheck` 를 선언하면 그만큼 가벼워진다 —
다만 **타입 검사는 더 적게 본다**(번들러에서만 깨지는 것은 못 본다). 무엇을 살지는 은하가 정한다.
줄었는지는 라운드 수로 잰다.

## 명령의 자물쇠는 어디서 왔나 — 사건 기록

[사용법](02-usage.md) 은 명령마다 **무엇을 치고 · 무엇이 나오고 · 함정 하나**만 적는다.
그 함정들이 **어느 사고에서 나왔는지**를 여기 모아 둔다 — ⛔ 사연을 지우면 다음 사람이
같은 자리를 다시 밟는다.

### `session` — 세션 없이 도는 화면 시험은 **셸만 잰다**

로그인 뒤 화면이 본체인 저장소에서, 세션 없이 화면 시험을 돌렸다. backoffice 를 자격 없이
열었더니 「장시간 사용 이력이 없어 자동 로그아웃 되었습니다」 모달이 떴다 — 그 상태로
아무리 초록이 나와도 **로그인 뒤 화면은 한 번도 안 잰 것**이다.
⛔ 그걸 「화면 시험 통과」라고 부르면 그게 이 저장소가 제일 싫어하는 거짓 초록이다.

### `gh-auth` — 계정 둘인 기계에서 **활성이 아닌 쪽을 찍었다**

`gh` 는 여러 계정을 들 수 있고 그중 **활성 계정 하나**만 실제로 쓰인다.
⛔ 첫 번째를 활성으로 읽으면 **틀린다** — 실측으로 그렇게 틀렸다.
그래서 이 도구는 로그인 **전에도** 계정을 찍고 **끝난 뒤에도** 다시 찍으며,
바뀌었으면 전/후를 함께 적고(`switched`), 다른 계정이 더 있으면 **몇이 있는지** 말한다.
⇒ `repos` 의 「`gh auth login` 은 사람이 한다」라는 금지는 뒤집혔지만 **이유는 안 뒤집혔다.**

### `branches` — 기본 가지를 받아 놓고 「이 저장소를 쟀다」

안 주면 `clone` 은 **원격의 기본 가지**를 받는다. 그런데 잴 대상이 `main` 이 아닌 경우가
흔하다 — 이 우주의 실측 은하들부터가 작업 가지에 있다.
⛔ 기본 가지를 받아 놓고 「이 저장소를 쟀다」고 말하면 **다른 코드를 잰 것**이다.
⛔ 그래도 **기본 가지가 무엇인지는 못 잰다**(`git ls-remote --heads` 는 `HEAD` 를 안 준다) —
「아마 main 이겠지」로 표시하지 않고, 받은 뒤 `clone` 이 **실제 가지를 찍는다.**

### `adopt` — 도구가 **자기 입으로 경고하고** 사람에게 맡기고 있었다

도구는 이렇게 경고하고 있었다 — 「목록에 이름을 안 올리면 관측이 **아무것도 안 재고 초록불**을
낸다」(R121). **그 위험을 사람 손에 맡기고 있었다.** 그래서 좌표 두기와 목록 올리기가
**한 명령**이 됐다. ⛔ 그래도 판단은 사람이 한다: `TODO:` 가 남아 있으면 안 들이고,
같은 이름의 좌표가 있으면 멈추고, 커밋되는 `galaxies/` 대신 `galaxies.local/` 에 쓴다.

### `verify` — **안 돈 축이 화면에서 사라졌다** (R146)

진짜 은하에서 lint 가 빨간불이 나자 출력은 `❌ lint` 한 줄뿐이었고, build·test 가 통과한
것인지 아예 안 돈 것인지 읽는 사람이 가릴 방법이 없었다 — **없는 줄은 초록불처럼 읽힌다.**
지금은 안 돈 축도 **이름을 부르며** ⚪ 로 나온다. **순서를 지키는 것과 말하지 않는 것은 다른 일이다.**

같은 라운드에서 `commands.typecheck` 도 잡혔다. 예전엔 `commands.extraGates.typecheck`
**한 자리만** 읽어서, 좌표에 `commands.typecheck` 를 적어 둔 은하의 타입 검사가
**한 번도 안 돌았다** — 화면에서도 사라진 축이라 아무도 못 봤다.

### `--contract-first` — 왜 **「먼저」**인가

에이전트가 **구현을 본 뒤** 테스트를 쓰면 **통과하기 쉬운 것**을 쓴다. 그건 채점이 아니라
자기 채점이다. 구현 전에 받고 빨간불을 확인하면, 그 계약은 **적어도 무언가를 재고 있다**는
것이 기계로 확인된다. ⚠️ **기본은 꺼져 있다** — 모델 호출이 한 번 더 들고, 이것이 결과를
낫게 하는지는 아직 안 쟀다. 끄면 요구사항 충족은 **여전히 아무도 안 잰다.**

### `learn-cards` — 자리는 있는데 **채우는 길이 유료 하나뿐**이었다

빅뱅은 `<은하>/universe/knowledge/*.md` 를 읽어 에이전트의 **첫 관측**에 끼워 넣는다.
그 자리는 **이미 있었는데** 채우는 길이 `universe extract --write` 하나뿐이었다.
⚠️ 실측: 궤적의 `nebula-start` **2458줄 중 `skillCards` 가 채워진 것은 1줄**이다 —
자리는 있는데 **사실상 안 채워져 있었다.**
⇒ 관문의 반려 사유는 **규칙이 스스로 쓴 결정론적 문장**이라 요약이 필요 없다. 세어서
**반복되는 것만** 골라내면 그대로 브리핑이다. ⛔ **모델을 안 부른다.**

### `blueprint` — 「공짜인 줄 알고 돌렸다」를 막는 법

「**불러온 레포에 페이지별 아키텍처, 메뉴별 설명이 없으면 그 구조부터 분석시켜서 셋팅**」의 그 칸이다.
⛔⛔ 기본은 모델 호출 0회이고, `--write` 를 주면 **부르기 전에** 이렇게 말한다:

    ⛔ ⚠️ 토큰 사용량이 큽니다 — **모델을 N번** 부른다 (자리 하나에 한 번)
    ⛔ 자리마다 파일 최대 12개 · 파일마다 최대 6000자를 읽어서 보낸다

⚠️ 이 저장소가 가장 싫어하는 사건이 **「공짜인 줄 알고 돌렸다」**다(R145). 그래서 기본이
안전하고, 비용을 **부르기 전에** 수로 말한다. 파일이 잘리면 **몇 개를 안 봤는지도 말한다.**
⛔ 설명이 **일부만** 있어도 조용해지지 않는다 — 한 장이라도 있으면 나머지를 어긋남으로 센다.

### `repeat` · `loop` — 줄어들기만 하면 계속 도는 것이 아니다

⚠️ 줄어도 `--max` 에서 멈춘다 — **사람이 안 보는 사이에 몇 시간씩 도는 도구는 아무도 안 쓴다.**
⛔ 판정을 **두 자리에서 만들지 않는다.** 만들면 화면은 「판정 3건 붙였다」인데 관문은
「판단하지 않은 fail 3건」이 된다.

**`--watch` 가 못 하는 것:**
- 창은 **서버가 도는 기계**에 뜬다. 원격에서 화면만 연 사람은 그 창을 **못 본다.**
- **OS 마우스 커서 자체는 안 움직인다.** Playwright 는 페이지 안으로 이벤트를 쏜다 —
  클릭·입력·이동이 화면에 **반영되는 것**이 느리게 보이는 것이지, 바탕화면의 커서가
  끌려다니지는 않는다. ⛔ 「마우스가 움직인다」고 적지 않는다.

### `mutate` — 검증을 두 번 돌리는 값

⛔ **변이 전에 원본으로 한 번 돌린다.** 기준선이 이미 빨가면 무슨 변이를 넣든 「물었다」로
보인다 — 실측으로 재현했다(검증기를 늘 죽게 만들어 놓고 무해한 변이를 넣으니 **✅ 물었다**가 나왔다).
⚠️ 검증을 두 번 돌리니 값이 싸지 않다. 그런데 **거짓 초록보다 싸다.**
⚠️ 문법 검사는 `.mjs`·`.sh`·`.json` 에서만 **덤**으로 한다 — `.ts` 는 정상이어도 `node --check` 가
죽는다. 그리고 애초에 필요 없다: **깨진 파일은 기대한 사유를 못 낸다.**

### `hooks` — 「우주가 멀쩡한가」만 보고 **당신 코드는 안 봤다**

⭐ **2026-09-08 에 바뀐 것.** 그전까지 커밋 훅이 보던 것은 전부 **「우주가 멀쩡한가」**였다
(형식 · 링크 · 계약 · 부품). 그래서 우주를 깔고 훅까지 켠 저장소에서 **위반이 6건 늘어난
커밋이 그냥 지나갔다**(실측). 이제 `법칙 관측`(`observe`)이 훅에 있다 — 관측이 싸기 때문에
걸 수 있다(진짜 은하 1,407파일에서 0.73초 · 실측).
⛔ 「느려서 뺐다」가 아니라 **아무도 안 넣었던 것**이다.

⚠️ **안내가 훅을 못 따라간 적이 두 번 있다.** R73 에 넷을 적는데 다섯이 돌았고,
2026-09-08 에는 「훅에서 읽는」 장치를 만들어 뒀는데도 훑개가 **들여쓴 호출을 못 봐서**
하필 방금 들어온 `법칙 관측` 만 안내에서 빠졌다. 지금은 `lib/gates.mjs` 의 `hookLabels`
한 자리가 훑고, 시험이 **훅과 안내가 같은 것을 세는지** 문다.

⚠️ 훅이 있는 이유: 관문이 `round close` 에만 있던 때 `a11y/img-alt` 의 패턴에 `NEVERMATCH` 가
커밋돼 **그 규칙이 아무것도 잡지 못하는 상태로 HEAD 에 있었다.**

### `observe` — 기준선이 **도장**이 되던 자리 (R64)

기준선을 올릴 때 사유를 요구하기 전에는, 위반을 늘리고 매번 `--update` 하면 우주가
**영원히 초록불**이었다 — 관문이 아니라 **도장**이 된다. 지금은 올리려면 `--why` 가 있어야 하고
(내릴 때는 안 묻는다 — 그게 목표다), 올린 이력이 쌓여 다음 관측이
「이 은하는 기준선을 N번 올렸다 — 빚이다」라고 말한다. `universe lint` 도 같은 래칫을 쓴다.

### `round audit` — 승격 4건이 **성운에서 사라진 적이 있다**

`close` 가 최고 판정이 아닌 축을 자동으로 성운에 싣는데, 실제로 승격 4건이 다른 작업에 덮여
**성운에서 사라졌다.** 그래서 로그를 정본, 성운을 파생으로 보고 대조하는 축이 따로 있다.

### `beacon` — 좌표가 없는 장이 **아무 말 없이** 빠지고 있었다

실측(2026-09-08): 이름표는 11장인데 좌표는 7장이라 `guide*` 넷이 **아무 말 없이** 빠지고
있었다. 저장소에서는 「썼다」인데 위키에서는 「없다」였고 **아무도 안 쟀다**(관측 법칙 §8).

## 관문은 어디서 왔나

[사용법](02-usage.md) 의 「관문에 걸려 있는 도구들」 표는 **무엇을 보는가**만 적는다.
각각이 **어느 사고에서 태어났는지**는 여기 있다 — 관문은 설계가 아니라 **사고의 화석**이다.

| 관문 | 왜 생겼나 |
|------|-----------|
| `universe lint` | 트렁크에 error 11건이 있어 깔자마자 빨간불이었다. 우주의 다른 모든 축은 기준선을 쓴다(R61) |
| `universe speed` | 그 법칙에 **관문이 없어 오래 장식이었다** — 예산을 읽는 코드가 하나도 없었다(R62) |
| `universe check` | 목록이 `round close` 안에만 있어 소비 저장소는 전부 돌릴 수 없었다(R58). ⛔ 수를 손으로 적지 마라 — 「지금 25개」라고 적혀 있었고 실제로는 34개였다 |
| `universe galaxy` | 40줄 좌표를 손으로 쓰는 것이 첫 벽이었다(R51) |
| `universe delivery` | `init` 이 42커밋 동안 깨진 우주를 만들고 있었다(R43) |
| `universe parts` | 재료가 조용히 틀리면 검사는 초록불을 낸다(R38·R47·R52) |
| `universe names` | 판단하지 않은 충돌 0개(R22) |
| `universe enumeration` | 열거 밖은 영영 안 보인다(관측 법칙 §9) |
| `universe fix` | 처방 없는 관문은 무시하는 법부터 가르친다(R35) |
| `universe learn` | 궤적에만 남은 관측은 실행되지 않는다(R48·R49) |
| `universe orphans` | 게이트는 별이 **서는지**만 봤다 — 이어졌는지는 세 자리에 적어 두고도 안 쟀다(R157) |
| `universe extract` | 실패는 성운으로 가는 길이 있었는데(`learn`) **성공은 갈 곳이 없었다** — 엔진에 코드가 있는데 아무도 안 불렀다(R155) |
| `universe messy` | 깨끗한 은하만으로는 재는 장치가 도는지 모른다(R37) |
| `universe facts` | 수치를 손으로 적었다가 여섯 번 낡았다(R55) |
| `universe structure` | 생성된 그림은 낡을 수 없지만 폴더는 바뀐다 |
| `universe proven` | 무발동 규칙을 본 팀이 「규칙이 약한 것인가」를 스스로 못 묻는다 — 더러운 은하가 배달되지 않기 때문이다(R93) |
| `universe corpora` | 겸업 오탐률을 다시 재려니 그 저장소가 없었다 — 「실측」은 「지금도 확인할 수 있다」로 읽힌다(R103) |
| `universe coordinates` | MIT 로 공개하고 밀었더니 은하 좌표의 `path` 가 **남의 홈 경로**였다(R152). ⚠️ 볼 파일을 손으로 셋 적어 뒀다가 넓혔다 — **3개 → 82개**(질문을 손으로 적으면 그 목록 밖은 안 보인다) |
| `universe quickstart` | 그 길이 조용히 깨져 있었다. 세 번째 명령이 **초록불인데 아무것도 안 쟀다**(R121) |
| `universe wiki` | 위키를 고치면 다음 발행이 덮어쓴다 |
| **3차 배선** | 3차는 **가장 비싼데 가장 안 재지던 갈래**였다 — 실주행은 사람의 사용량을 쓰므로 관문에 못 넣는다. 대본은 같은 배선을 **공짜로** 지난다(R147) |

⚠️ 3차 배선의 「게이트 축 넷이 이름을 내는가」를 셀 수 있게 된 것은 **R146 이 「안 돈 축은
화면에서 사라진다」를 고친 뒤**다. `[SOLVED]` 한 줄만 보면 게이트가 한 칸도 안 돌아도
초록으로 읽힌다 — **축의 이름이 찍혔는가**로 잰다.

## 도입을 권하지 않는 경우

- **팀이 규칙에 합의하지 않았다** — 관문이 헛돌고, 헛도는 관문은 무시하는 법부터 가르친다
- **`universe observe` 가 0건을 낸다** — 이미 게이트가 충분하다
- **CI 가 없다** — 관측소의 값어치 대부분은 자동 실행에서 나온다
- **스택이 React+Vite 가 아니다** — 플러그인을 먼저 만들어야 한다

## 성숙도로 자기 위치를 잰다

| 레벨 | 기준 |
|------|------|
| L1 | 뼈대만 |
| L2 | 법칙은 있으나 검사가 없다 |
| L3 | 법칙 + 형식 검사 |
| L4 | 법칙 + **동작 검사**(게이트·관문) + 전파 |
| L5 | **자기 개선 루프** — 낮은 평가가 다음 라운드의 작업이 된다 |

이 우주는 지금 **L4→L5 전환 중**이다. 궤도를 내고 성운 승격을 한 번 돌았지만,
성운에서 꺼내 도는 바퀴는 이제 막 시작했다.
