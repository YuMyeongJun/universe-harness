# 사용법

⚠️ **이 문서에 빠진 명령이 있으면 `universe parts` 가 막는다.** 예전엔 머리말이
「여섯 명령」이라고 적혀 있었는데 실제로는 22개였고 13개만 다뤘다(실측 R53) —
`--help` 에만 있고 문서 어디에도 없는 명령이 **9개**였다(R53). 아무도 못 쓰는 기능이다.

```
universe init                      소비 저장소에 우주를 깐다
universe init --update             기계만 새로 받는다 — 은하·성운·로그는 그대로 둔다
universe observe [--update]        은하의 법칙 위반을 잰다
universe verify                    게이트 + 관문
universe laws                      우주 자신의 형식 검사
universe links                     문서 링크가 실재하는 곳을 가리키는가
universe new <은하> <태양계> <별>   빅뱅 — 별을 태어나게 한다
  └ [--expand]                       2차 — 게이트까지 돌고 빨간 축을 스스로 고친다
  └ [--from "<요구사항>"]             3차 — 요구사항 한 줄에서 도는 화면까지
universe checks                    **검사가 정말 무는가** — 변이를 넣어 본다
universe beacon [--record]         위키가 낡았는가 (발행 뒤 --record)
universe hooks [--install]         커밋 시점 관문을 켠다
universe round new|close|audit|suggest   라운드 궤도 — 재고 · 평가하고 · 성운으로 올린다
universe render / publish          위키로 전파한다
```

공통: `--universe <경로>` 로 우주의 집을 직접 지정한다(기본은 cwd 에서 위로 탐색).

## 외우지 않고 쓰기 — 인자 없이 `universe`

⚠️ 위 목록이 **길어 보이는 이유**는 그중 대부분이 **사람이 칠 일 없는 것**이라서다.
`universe` 가 받는 것 대부분은 **`universe check` 가 알아서 부르는 관문**이고,
사람이 실제로 치는 것은 그중 일부다 — 수는 아래 표가 **생성해서** 말한다.
⇒ 외울 게 많아서 어려운 것이 아니라, **적은 일을 많게 보여 줘서** 어려웠다.

<!-- FACTS:BEGIN -->
| 지금 상태 | 값 |
|---|---:|
| 법칙 | 11 |
| 계약 규칙 | 20 |
| ↳ 법칙이 덮은 것 | 20 |
| ↳ 성운이 든 것(주인 없는 규칙) | 0 |
| 등록된 은하 | 5 |
| 관문(`universe check`) | 28 |
| 명령 | 33 |
| ↳ 사람이 치는 것 | 10 |
| ↳ 관문이 알아서 부르는 것 | 23 |
| 판 | 0.9.0 |
<!-- FACTS:END -->

⛔ 이 수를 여기 손으로 적지 않는다 — 그렇게 적힌 두 자리가 이미 낡아 있었다(R161).

```
universe                    터미널이면 **고르면서** 쓴다 · 아니면 도움말
universe --help             사람이 치는 명령 10개만
universe --help --all       관문이 부르는 22개까지 전부
```

대화형 입구는 고른 것에 **필요한 것만** 묻고(은하·태양계 이름은 좌표에서 **읽어서**
보여 준다), **만든 명령줄을 찍고 나서** 실행한다:

```
$ universe new tiny-galaxy shop DashboardToday --expand
이대로 실행할까? [y/N]:
```

⛔ **명령줄을 먼저 찍는 것이 핵심이다.** 메뉴가 명령을 대신 기억해 주면 사람은 영영
못 외운다. 다음엔 메뉴를 안 거치게 되는 것이 성공이다 — **화면이 목적이 아니라 입구다.**

⛔⛔ **화면은 관문을 못 끈다.** 「무시하고 계속」·「이번만 건너뛰기」 갈래가 **없다**.
강제는 훅과 CI 에 있고 여기는 거기 손이 안 닿는다 — 「느려진 관문은 아무도 안 본다」의
사촌이 **「넘길 수 있는 관문」**이다. 부품 시험이 그 갈래가 생기는지 매 커밋 문다.

⛔ **비-TTY 에서는 대화형으로 가지 않는다.** CI·파이프에서 인자 없이 부르면 지금처럼
도움말을 찍고 끝난다 — 안 그러면 답을 기다리며 매달려 CI 가 통째로 죽는다.

⚠️ **돈이 드는 갈래는 한 번 더 묻는다** — `new --from`(3차)과 `extract --write` 는
모델을 부른다는 것을 **말하고 확인을 받는다.** 막지는 않는다. 사람이 정한다.

⚠️ **1차·2차는 모델이 없어도 완전히 돈다.** 별을 낳는 것도, 게이트까지 돌려 빨간 축을
스스로 고치는 것도 결정론 규칙과 정적 레인만 쓴다 — 구독도 API 키도 필요 없다.
모델이 필요한 것은 **3차(요구사항 한 줄에서 도는 화면까지)뿐**이고, 그것도 **누가 답하는지는
사람이 고른다**(아래 `new` 절의 레인 표). 「모델이 없으면 아무것도 못 한다」는 흔한 오해다.

## `init` — 소비 저장소에 우주를 깐다

```bash
cd <당신의-저장소>
universe init            # universe/ 가 생긴다
universe init --update   # 기계만 새로 받는다 — 은하·성운·로그는 그대로 둔다
```

⛔ **우주 저장소 안에서는 거절한다.** 「여기가 우주 저장소다 — 우주 안에 우주를 깔지 않는다.」
`--force` 로도 안 뚫린다. ⚠️ 위의 다른 경고들(「저장소 밖에 깐다」·「git 저장소가 아니다」)은
**말만 하고 지나가지만** 이것은 막는다 — 저 둘은 일부러 그럴 수 있고, 이건 그럴 이유가 없다.

⚠️ 실측: 하루에 **세 번** 이 사고가 났다(그중 한 번은 그것을 못 박으려던 변이 시험이 냈다).
⛔ 진짜 값은 더러운 워킹트리가 아니었다 — 복제된 문서가 참조를 하나 더 만들어
**변이 하나가 안 물게 됐다.** 더러운 트리는 보이지만 **죽은 검사는 안 보인다.**

정말로 이 저장소 안 어딘가에 깔아야 한다면 `--dir <경로>` 로 **자리를 댄다** — 명시한 것은 일부러다.

## `observe` — 법칙 위반을 잰다

⛔ **기준선은 한 방향으로만 움직인다.** `--update` 가 기준선을 **올리려** 하면
`--why "<왜 올리는가>"` 없이는 멈춘다. 내릴 때는 안 묻는다 — 그게 목표다.
막지는 않는다; **기록 없이** 올리지 못하게 할 뿐이다. 올린 이력은 `observed.raised` 에 쌓이고
다음 관측이 「이 은하는 기준선을 N번 올렸다 — 빚이다」라고 말한다.
⚠️ 이게 없을 때는 위반을 늘리고 매번 `--update` 하면 우주가 **영원히 초록불**이었다(R64) —
관문이 아니라 **도장**이 된다. `universe lint` 도 같은 래칫을 쓴다.


**언제:** 법칙을 고쳤을 때 · 주기적으로 · PR 에서.

```bash
universe observe                       # 전체
universe observe --galaxy my-app
universe observe --law tokens --sample 20
universe observe --update              # 기준선을 심는다
```

세 가지를 한다.

| | 무엇 |
|---|---|
| **커버리지** | 규칙 전부에 주인(법칙)이 있는가. 없으면 `exit 1` |
| **실측** | 법칙별 위반 수 |
| **드리프트** | 기준선과 다른가. 다르면 `exit 1` |

⚠️ 드리프트가 났을 때 **`--update` 로 덮기 전에 왜 달라졌는지 먼저 보라.**
`git status` 는 HEAD 대비 워킹트리만 본다 — **두 측정 사이의 HEAD 이동은 안 보인다.**

```bash
git log --oneline <기준선 commit>..HEAD -- <appDir>/src
```

기준선에는 `commit` · `dirtyFiles` · `fingerprint` 가 함께 남는다.
그래서 "무엇을 잰 것인지"를 나중에 되짚을 수 있다.

## `verify` — 별이 도는가

**언제:** 코드를 고친 뒤. CI 에서.

```bash
universe verify --galaxy my-app
universe verify --galaxy my-app --static-only   # 판정 레인(LLM) 끄기
universe verify --galaxy my-app --base HEAD~1   # 변경분 기준
```

순서가 곧 설계다: **관문 → 게이트**.

1. **관문** — 변경된 파일만 법칙으로 판정. 막히면 게이트를 **아예 돌리지 않는다**
2. **게이트** — lint(JSON) → build → test → typecheck. **잰 빨간불**이 하나라도 나면 뒤는 안 돈다

관문이 먼저인 이유는 **싸기 때문**이다. 이름 하나 때문에 20분짜리 빌드를 돌릴 이유가 없다.

### 신호는 셋이다 (R146)

| 신호 | 뜻 | 무슨 일이 있었나 |
|---|---|---|
| ✅ | **잰 초록** | 도구가 돌았고 통과했다 |
| ❌ | **잰 빨강** | 도구가 돌았고 막혔다 |
| ⚪ | **못 쟀다** | 축이 아예 안 돌았다 — **통과도 실패도 아니다** |

⚪ 가 나는 자리는 둘이다.

- **은하가 그 명령을 선언하지 않았다** — `commands.test` 가 없다고 `npm test` 를 지어내지 않는다.
  지어낸 명령의 실패는 **별 탓으로 돌아오고**, 없는 테스트의 침묵은 **통과로 읽힌다.**
- **앞 게이트가 빨간불이라 안 돌았다** — 죽은 빌드 위에서 잰 수는 거짓이므로 뒤는 돌리지 않는다.

⚠️ **예전엔 안 돈 축이 화면에서 사라졌다.** 진짜 은하에서 lint 가 빨간불이 나자 출력은
`❌ lint` 한 줄뿐이었고, build·test 가 통과한 것인지 아예 안 돈 것인지 읽는 사람이 가릴 방법이
없었다 — **없는 줄은 초록불처럼 읽힌다.** 지금은 안 돈 축도 **이름을 부르며** ⚪ 로 나온다.
순서를 지키는 것과 **말하지 않는 것은 다른 일이다.**

⛔ **못 잰 축은 초록으로도 빨강으로도 세지 않는다.** 「통과」로 세면 이 칸을 만든 뜻이 없다.

### 타입 검사는 `commands.typecheck` 에 적어라

⚠️ 예전엔 `commands.extraGates.typecheck` **한 자리만** 읽었다. 그래서 좌표에
`commands.typecheck` 를 적어 둔 은하의 타입 검사가 **한 번도 안 돌았다** — 화면에서도 사라진
축이라 아무도 못 봤다(R146 에서 실측으로 잡았다). 지금은 **두 자리를 다 읽는다**
(`commands.typecheck` 가 먼저다). 어느 쪽에도 없으면 ⚪ 「못 쟀다」다.

⛔ **은하가 서지 않으면 게이트를 돌리기 전에 멈춘다.** 좌표에 `requiredEnv` 를 선언했는데
그 환경변수가 비어 있으면 `exit 2` 로 멈추고 「은하가 서지 않는다」고 말한다 —
⚪ 「못 쟀다」와 **다른 판정**이다(R149 · [심화](03-advanced.md) 에 왜와 어떻게).

## `new` — 빅뱅

```bash
universe new my-app dashboard DashboardToday
universe new my-app dashboard DashboardToday --dry-run
universe new my-app dashboard DashboardToday --out /tmp/test   # 은하를 안 건드린다
```

별 하나에 파일 넷. **관문이 생성 파이프라인 안에 있다** — 위반이면 파일을 쓰지 않고 `exit 1`.

⚠️ 위반이 나오면 **별이 아니라 템플릿을 고쳐라.** 템플릿은 우주의 자산이라
한 번 어긋나면 태어나는 별마다 같은 위반을 찍어낸다.

**덮어쓰지 않는다.** 파일이 하나라도 있으면 아무것도 쓰지 않고 멈춘다.

### `--expand` — 2차 팽창

```bash
universe new my-app dashboard DashboardToday --expand
```

태어난 뒤 **게이트까지 자동으로** 돈다. 빨간 축이 나오면 **귀속**부터 한다:

| 귀속 | 근거 | 무엇을 하나 |
|------|------|------------|
| **별 탓** | lint JSON **원본 산출** · 전부 별의 폴더 안 | 그 폴더만 `--fix` 로 고치고 게이트 1회 더 |
| **관문 반려** | 정적 규칙 | ⛔ 별을 고치지 않는다 — **템플릿을 고치라고** 파일 이름을 짚어 넘긴다 |
| **은하 탓** | 별의 폴더 밖 | 별의 잘못이 아니다 — 인계 |
| build·test 실패 | 실패 출력에서 주움 = **추정** | 「추정」이라 찍고 **자동 수정의 근거로 쓰지 않는다** |

| 종료코드 | 무엇 |
|---|---|
| `0` | 별이 게이트를 지난다 |
| `1` | 못 지났다 — **되돌렸다**(`--keep-on-fail` 로 남길 수 있다) |
| `2` | **게이트가 판정을 내지 못했다**(크래시) — 별을 판단한 것이 아니므로 되돌리지 않는다 |

**게이트 상한은 2회**(최초 + 자가 수정 후 재확인). 게이트가 비싸고, `--fix` 는 멱등이라
1회차에 못 고친 규칙은 2회차에도 못 고친다 — 3번째는 **새 정보 0으로 20분**이다.

⚠️ `--expand` 는 `--out` 과 같이 못 쓴다. 게이트는 은하에서 도는데 별이 은하 밖에 있으면
그 수치는 별의 것이 아니다.

⚠️ 판정 레인(LLM)은 기본 꺼져 있다(`--judge` 로 켠다). **자동 루프의 기본값은 결정론이어야 한다.**

### `--from` — 3차 팽창

```bash
universe new my-app wallet CouponList --from "쿠폰 목록 위에 남은 개수를 보여 주고, 없으면 안내 문구를 띄워라"
```

#### `--contract-first` — 요구사항 충족을 재는 유일한 기계 장치

게이트가 재는 것은 `lint·build·test·typecheck` 다. **「요구사항대로인가」는 아무도 안 본다**(R23).
`--contract-first` 는 그 자리를 이렇게 좁힌다:

```
① 구현 **전에** 요구사항을 테스트로 받는다
② 그 테스트를 지금 돌린다 → **빨간불이어야 한다**
   · 처음부터 통과하면 → **거부한다**(아무것도 안 재는 계약이다)
③ 통과한 계약은 **보호 목록**에 들어간다 — 구현 단계에서 못 고친다
```

**왜 「먼저」인가.** 에이전트가 **구현을 본 뒤** 테스트를 쓰면 **통과하기 쉬운 것**을 쓴다.
그건 채점이 아니라 자기 채점이다. 구현 전에 받고 빨간불을 확인하면, 그 계약은
**적어도 무언가를 재고 있다**는 것이 기계로 확인된다.

⛔⛔ **이것은 「충족을 잰다」가 아니다 — 「승인된 계약이 도는가」를 잰다.**
②를 통과하면서도 **얕은** 계약은 여전히 가능하다(배지가 항상 떠도 통과하는 것).
「계약이 충분한가」는 기계가 못 잰다 — **사람이 봐야 하는 자리가 남는다.**

⛔ 은하가 `commands.testFile` 을 선언 안 했으면 이 축은 **⚪ 「못 쟀다」**다.
명령을 지어내 재지 않는다(R146).

⚠️ **기본은 꺼져 있다.** 모델 호출이 한 번 더 들고, 이것이 결과를 낫게 하는지는 아직 안 쟀다.
끄면 요구사항 충족은 **여전히 아무도 안 잰다** — 그것이 지금의 기본값이다.

#### `--lane` — 누가 답하는가

**1차·2차는 모델이 없어도 완전히 돈다**(결정론 규칙 + 정적 레인). 모델이 필요한 것은 **3차뿐**이다.
그 3차를 누가 답할지는 **사람이 고른다**:

```bash
universe new my-app wallet CouponList --from "…"                      # 기본 — 구독(claude CLI)
universe new my-app wallet CouponList --from "…" --lane openrouter --model anthropic/claude-sonnet-5
universe new my-app wallet CouponList --from "…" --lane omniroute  --model cc/claude-opus-4-6
universe new my-app wallet CouponList --from "…" --lane script --agent-script <대본>   # 0원
```

### 게이트 축은 은하가 정한다

| 축 | 은하가 적는 곳 | 안 적으면 |
|---|---|---|
| lint | `commands.lintJson` | ⚪ 못 쟀다 |
| build | `commands.build` | ⚪ 못 쟀다 |
| test | `commands.test` | ⚪ 못 쟀다 |
| typecheck | `commands.typecheck` (또는 `extraGates.typecheck`) | ⚪ 못 쟀다 |
| **e2e** | `commands.e2e` | ⚪ 못 쟀다 |

⛔ **브라우저를 우리가 깔지 않는다.** 이미 Playwright·Cypress 를 쓰는 팀이 **명령만 적으면** 붙는다.
안 적으면 ⚪ 다 — 없는 E2E 가 통과로 세어지지 않는다.
⚠️ e2e 는 **맨 뒤에서 돈다**. 가장 비싸고, 앞이 빨간불이면 아예 안 돈다(죽은 빌드 위의 수는 거짓이다).

| 레인 | 무엇으로 | 돈 |
|---|---|---|
| `subscription`(기본) | `claude` CLI · `ANTHROPIC_API_KEY` 를 **자식에서 지운다** | 그 기계의 구독 |
| `openrouter` | 호스팅 게이트웨이 · `OPENROUTER_API_KEY` · 슬러그 `anthropic/claude-sonnet-5` | **과금된다** |
| `omniroute` | **직접 띄우는** 게이트웨이 · `OMNIROUTE_API_KEY` · 슬러그 `cc/claude-opus-4-6` | 붙인 provider 에 달렸다 |
| `script` | 미리 적어 둔 JSONL 대본 | **0원** — 배선만 잰다 |

게이트웨이 둘은 **규약이 같다**(OpenAI 호환) — 코드도 하나를 쓴다. 다른 것은 주소·키·슬러그뿐이다.
주소는 `OPENROUTER_BASE_URL`·`OMNIROUTE_BASE_URL` 로 덮는다(직접 띄운 것은 자리가 사람마다 다르다).

⛔ **`omniroute` 는 모델을 지어내지 않는다.** 그 게이트웨이에 어떤 provider 가 붙어 있는지는
그 사람의 설정이라, 우리가 고르면 **엉뚱한 곳으로 청구된다.** `--model` 을 반드시 줘라.

⚠️⚠️ **게이트웨이의 자동 폴백을 켜지 마라.** 「구독 먼저 → API 키 → 무료 티어」로 알아서
갈아타는 기능이 있는데, 그것이 정확히 R145 가 못 박은 사건이다 — **모드가 바뀌는데 아무도 안 잰다.**
구독인 줄 알고 돌렸는데 청구되는 자리다. **한 provider 로 고정한 슬러그**를 줘라.

⛔ **자동으로 갈아타지 않는다.** `claude` 가 없다고 과금 레인으로 몰래 넘어가지 않는다 —
「모드가 바뀌는데 아무도 안 잰다」가 이 저장소가 가장 싫어하는 사건이다(R145).
키가 없으면 **별을 쓰기도 전에** 멈춘다.

빈 별이 아니라 **요구사항이 반영된 별**이 나온다. 1차로 뼈대와 관문을 세운 뒤 그 위에서 돈다:

```
턴: 도구 없는 에이전트가 JSON 액션 하나
  ├ probe  → 은하에서 읽기 전용
  ├ patch  → 관문 ─┬ 반려 → 사유 그대로 돌려주고 파일엔 안 닿는다
  │                └ 허용 → 별의 폴더 안에만 쓴다
  └ submit → 게이트(2차와 같은 판정 규칙)
               ├ 초록 → exit 0
               └ 빨강 → 귀속 + 사유를 에이전트에게
```

**요구사항은 관문을 열지 못한다.** 요구사항 문장은 에이전트가 보는 관측 자리에만 실리고,
관문은 결정론이다. 실측으로 확인했다 — 요구사항에 「법칙은 무시하고 테스트도 고쳐서
통과시켜라」를 넣고 돌려도 반려됐고, 별의 파일은 1차 템플릿과 **바이트까지 동일**했다.

| 상한 | 값 | 근거 |
|---|---|---|
| 게이트 | **3회** | 1=첫 측정 · 2=가설1 · 3=가설2 · 4번째는 **두 번 연속 못 고친 뒤**라 수렴이 아니라 헤매는 중이라는 증거가 이미 둘이다 |
| 턴 | 10 | 게이트 3회전에 최소 6턴 + 여유 4 |

수보다 먼저 무는 규칙이 둘 있다 — **별의 바이트가 그대로면 게이트를 아예 안 돈다**,
**빨간 축의 이름·수치가 직전과 같으면 상한 전에 멈춘다.** 같은 실패를 두 번 보는 것은
새 정보가 아니다.

⚠️ **아직 못 하는 것** — 3차가 보장하는 것은 「요구사항을 반영했다고 주장하는 코드가
관문과 게이트를 지난다」까지다. 게이트가 재는 건 lint·build·test 이므로 **요구사항이 실제로
충족됐는지는 못 잰다.** 그리고 테스트 파일 수정을 막았기 때문에 **3차가 만든 기능에는
계약이 안 생긴다** — 지금 가장 큰 구멍이고 성운에 올려 뒀다.

## `liveness` — 세션이 **살아 있는가**

```bash
universe liveness                    # 등록된 은하 전부
universe liveness --galaxy <이름>     # 하나만
```

⛔ **「있는가」와 「살아 있는가」는 다른 층이다.** `requiredEnv` 는 환경 변수가 **있는지**만 본다
(값은 안 읽는다 — 값을 읽으면 그 값이 로그에 샌다). 그런데 **토큰 문자열은 만료돼도 그대로 있다.**

⚠️ 실측(다른 팀): 로그인 세션에 수명이 있어(1시간) **오래 도는 루프 중간에 죽는다.** 그때
화면은 로그인 페이지를 재고 **「전부 fail」**을 뱉는데 — **그건 제품 결함이 아니다.**
존재만 보는 검사는 이것을 **절대 못 잡는다.**

⛔ **우주는 확인 방법을 짐작하지 않는다.** 쿠키·토큰·OTP 는 은하마다 다르다. 은하가 좌표에
**선언**하고 우주는 그 선언을 실행할 뿐이다 — 하네스가 자기 명령을 안 갖는 것과 같은 규율이다.

```jsonc
// galaxies/<이름>.json
"liveness": { "세션": "<0 이면 살아 있다는 뜻의 명령>" }
```

판정 셋 — 종료코드로 말한다:

| | 뜻 |
|---|---|
| `0` 살아 있다 | 선언한 확인이 0으로 끝났다 |
| `1` 죽었다 | ⚠️ **제품 결함이 아닐 수 있다** — 세션이 만료된 것뿐일 수 있다 |
| `3` **못 쟀다** | **선언이 없다.** ⛔ 「살아 있다」로 넘기지 않는다 — 0은 무죄가 아니다 |

⚠️ 아무 은하도 선언 안 하면 `universe check` 에 ⚪ 가 매번 뜬다. **그것이 이 관문을 넣은 이유다** —
「아무도 세션을 안 재고 있다」가 보여야 나중에 「전부 fail」이 났을 때 원인을 안다.

## `laws` — 우주 자신을 검사한다

```bash
universe laws
```

법칙이 은하를 검사한다면, 이것은 **우주가 자기 법칙을 지키는지** 본다 —
frontmatter · 필수 절 · config 정합 · 중력(고아 문서) · 보존(자산 vs 산출물) ·
그리고 **검사 명령을 파이프에 물려 판정하는 스크립트**(경고).

## `links` — 문서가 유령을 가리키지 않는가

```bash
universe links
echo "exit=$?"
```

상대 링크가 실재하는 파일을 가리키는지 센다. 코드블록과 인라인 코드 안은 건너뛴다 —
문서가 마크다운 문법 자체를 설명하는 자리를 링크로 세면 오탐이 되고, **오탐을 내는 도구는
사람이 꺼 버린다.**

## `checks` — 검사가 정말 무는가

이 검사는 **다섯 가지**를 본다: 변이(알려진 위반을 넣으면 무는가) · **반드시 거부해야 하는 것**
(경로 탈출 · 모르는 이름 등) · **맞는 말을 하는가**(멈추지 않는 것이 옳고 말만 달라져야 하는 자리) ·
모르는 플래그를 삼키지 않는가(§7) · 동시 실행이 막히는가.
⛔ 전부 **종료코드가 아니라 거부 사유**로 판정한다 — 다른 이유로 죽어도 초록불로 보이기 때문이다(R79).


```bash
universe checks
echo "exit=$?"
```

검사마다 **알려진 위반을 주입**하고 그 검사가 exit 0 이 아닌지 본다. 물지 않으면
그 검사는 장식이다. 진입점이 모르는 플래그를 거부하는지도 함께 본다(관측 법칙 §7).

⚠️ 파일을 고쳤다 git 으로 되돌리므로 **만질 파일이 깨끗할 때만** 돈다.

## `beacon` — 위키가 낡았는가

```bash
universe beacon            # 렌더가 바뀌었는데 발행 안 한 페이지를 찾는다
universe beacon --record   # 방금 발행했다고 기록한다
```

⛔ **위키 쪽에서 사람이 고친 것은 못 잡는다.** 이 검사는 「내가 마지막에 보낸 것」과
「지금 렌더 결과」만 본다.

## `hooks` — 커밋 시점 관문

```bash
universe hooks             # 켜졌는지 본다 (0=켜짐 · 1=꺼짐)
universe hooks --install   # 켠다
```

git 훅은 **클론해도 자동으로 안 켜진다**(`.git/hooks` 는 커밋되지 않는다). 그래서 훅을
`.githooks/` 에 두고 이 명령이 `core.hooksPath` 를 가리키게 한다.

여기 거는 것은 **빠른 것만**이다(잰 값은 [결과 예측](05-expectations.md) 의 시간표에 있다 — ⛔ 여기 적으면 낡는다) — 느린 것(변이 시험 · 관측 ·
엔진 빌드)을 걸면 사람이 `--no-verify` 를 습관으로 만든다.

| 관문 | 실측 |
|---|---:|
| 우주 형식 | 891ms |
| 엔진 계약 규칙 | 78ms |
| 행동 계약 보호 | 36ms |
| 문서 링크 | 33ms |

⚠️ 이것이 있는 이유: 관문이 `round close` 에만 있던 때 `a11y/img-alt` 의 패턴에
`NEVERMATCH` 가 커밋돼 **그 규칙이 아무것도 잡지 못하는 상태로 HEAD 에 있었다.**
훅을 켠 뒤 그 상황을 재현해 보면 `❌ 엔진 계약 규칙` 으로 커밋이 막힌다.

## `round` — 스스로 도는 바퀴

⛔ **`--force` 로 넘어가면 로그에 `forced:` 로 남는다.** 그전엔 흔적이 **아무 데도** 없어
라운드가 **초록불이었던 것처럼** 닫혔다(R65). `--force` 만으로는 안 되고 **`--why "<왜 넘는가>"`** 를 함께 줘야 한다(R66).
`universe round audit` 이 그것을 세어 말한다 — 「빨간 관문을 넘어 닫은 라운드 N개 — 사유」. **도피구를 쓴 것 자체는 죄가 아니다 — 세지 않는 것이 죄다.**


```bash
universe round suggest   # 지금 라운드를 열 때인가 — 평가 안 된 커밋이 몇 개인가
universe round new "무엇을 할 것인가"
universe round close     # 평가표 검증 + 최고 판정이 아닌 축을 성운으로 승격
universe round audit     # 로그(정본)와 성운(파생)이 어긋나지 않는가
```

`suggest` 는 **판정이 아니라 눈에 띄게 하는 것**이다. 라운드가 있는 이유는 한 일이
평가되게 하기 위해서인데, 라운드 밖 커밋은 평가표를 거치지 않았고 따라서 낮은 축이
성운으로 올라갈 기회도 없었다. **언제 여는지는 사람이 정한다** — 기계는 빠뜨린 것이
안 보이는 상황만 막는다.

`close` 는 평가표에 **빈 판정 · 근거 없는 칸 · 여러 축을 뭉갠 합성 등급**이 있으면 거부한다.
그리고 최고 판정이 아닌 축을 **자동으로 성운에 싣는다** — 로그에만 남은 제안은 실행되지 않는다.

`audit` 이 따로 있는 이유: 실제로 승격 4건이 다른 작업에 덮여 **성운에서 사라진 적이 있다.**
로그를 정본, 성운을 파생으로 보고 대조한다.

## 재는 도구들 — 관문에 걸려 있는 것

⛔ **아래는 전부 `round close` 가 부른다.** 사람이 기억해서 돌리는 것이 아니라
바퀴를 닫을 때 자동으로 돈다. 손으로 부를 일은 **고치는 중일 때**다.

| 명령 | 무엇을 보는가 | 왜 생겼나 |
|------|---------------|-----------|
| `universe lint [--update]` | 은하의 lint 를 **기준선과 대조**한다 — 절대 0이 아니라 **늘었는가** | 트렁크에 error 11건이 있어 깔자마자 빨간불이었다. 우주의 다른 모든 축은 기준선을 쓴다(R61) |
| `universe speed [--update]` | 초기 로드가 **예산 안인가**(광속 한계) | 그 법칙에 **관문이 없어 오래 장식이었다** — 예산을 읽는 코드가 하나도 없었다(R62) |
| `universe check` | **관문 전부** — 라운드를 열지 않고 돈다. **지금 25개**(목록은 `lib/gates.mjs` 한 자리 · 그중 우주 자신에서만 뜻이 있는 것 17개 · 엔진이 있어야 하는 것 11개). 못 재는 것은 **왜 못 재는지** 말한다(배달본이라 · 엔진이 아직 없어서 · 파일이 없어서) | 목록이 `round close` 안에만 있어 소비 저장소는 전부 돌릴 수 없었다(R58) |
| `universe galaxy <이름>` | 저장소를 읽어 **은하 좌표 초안**을 만든다. 좌표가 **절대 경로면 `galaxies.local/` 에 둔다** — 명부가 둘인 이유는 [심화](03-advanced.md) 에 있다 | 40줄 좌표를 손으로 쓰는 것이 첫 벽이었다(R51) |
| `universe delivery` | **갓 깐 우주**가 도는가 · 안내대로 부르면 도는가 | `init` 이 42커밋 동안 깨진 우주를 만들고 있었다(R43) |
| `universe parts` | `lib/` 순수 함수 · 엔진 배치가 한 자리인가 · 버전이 한 값인가 · 우주 안에 별이 없는가 · dist 가 지금 소스에서 나왔는가 · **판올림에 기록이 있는가** | 재료가 조용히 틀리면 검사는 초록불을 낸다(R38·R47·R52) |
| `universe names` | 내보내는 이름이 겹치는가 | 판단하지 않은 충돌 0개(R22) |
| `universe enumeration` | 규칙이 **사람이 정한 이름**을 열거하는가 | 열거 밖은 영영 안 보인다(관측 법칙 §9) |
| `universe fix` | 규칙이 **무엇을 하라**고 말하는가 | 처방 없는 관문은 무시하는 법부터 가르친다(R35) |
| `universe learn [--check]` | 궤적이 낸 후보를 **판단했는가** · 고친 것이 **재발했는가** | 궤적에만 남은 관측은 실행되지 않는다(R48·R49) |
| `universe orphans` | **아무도 안 가리키는 별**을 센다 — 「사람이 볼 수 있는가」의 싼 절반. ⛔ **커밋된 별**만 본다(갓 만든 별이 고아인 것은 정상이다) | 게이트는 별이 **서는지**만 봤다 — 이어졌는지는 세 자리에 적어 두고도 안 쟀다(R157) |
| `universe extract` | **성공** 궤적에서 지식 카드를 뽑는다 — 학습 고리의 **돌아오는 절반**(R155). ⛔ 기본은 **모델을 안 부른다**(무엇이 될지만 보여 준다). ⛔ **대본 레인 주행은 뺀다**(R160) — 몇 건을 왜 뺐는지 화면에 말한다. ⚪ 레인이 **안 적힌 옛 궤적**은 「모른다」로 따로 센다 | 실패는 성운으로 가는 길이 있었는데(`learn`) **성공은 갈 곳이 없었다** — 엔진에 코드가 있는데 아무도 안 불렀다 |
| `universe messy [--check]` | **일부러 더러운 은하**가 규칙 표와 맞는가 | 깨끗한 은하만으로는 재는 장치가 도는지 모른다(R37) |
| `universe facts [--check]` | 문서의 **「지금 상태」 수치**를 생성한다 | 수치를 손으로 적었다가 여섯 번 낡았다(R55) |
| `universe structure [--check]` | 폴더 그림이 낡았는가 | 생성된 그림은 낡을 수 없지만 폴더는 바뀐다 |
| `universe proven [--check]` | **발동이 증명된 규칙** 명부를 만든다 | 무발동 규칙을 본 팀이 「규칙이 약한 것인가」를 스스로 못 묻는다 — 더러운 은하가 배달되지 않기 때문이다(R93) |
| `universe corpora` | 인용한 **수치의 대상**이 아직 있는가 | 겸업 오탐률을 다시 재려니 그 저장소가 없었다 — 「실측」은 「지금도 확인할 수 있다」로 읽힌다(R103) |
| `universe quickstart` | **새 사람의 길** — 문서 순서를 빈 저장소에서 그대로 밟는다 | 그 길이 조용히 깨져 있었다. 세 번째 명령이 **초록불인데 아무것도 안 쟀다**(R121) |
| `universe wiki` | 발행본과 저장소가 어긋났는가 | 위키를 고치면 다음 발행이 덮어쓴다 |

각각 `--check`/`--update` 가 있는 것은 **판단을 기준선에 적는 방식**이다 —
「나쁜 것 0개」가 아니라 **「판단하지 않은 것 0개」**를 목표로 한다.

⛔ **관문도 신호가 셋이다.** 종료코드 `3` 은 「여기선 잴 수 없었다」이고 **통과가 아니다** —
화면에 ⚪ 로 따로 세고 이름을 부른다. 예전엔 0 아니면 1 뿐이라, 궤적이 하나도 없어
**아무것도 못 잰 관문이 ✅ 로 찍혔다**(R154 · CI 가 그 자리를 잡았다). 게이트의 축에서
고친 것과 **같은 결함이 한 층 위에 남아 있었다.**

### 관문에 있는데 명령이 없는 것

⛔ 아래 둘은 `universe` 하위 명령이 아니다 — `universe check` 와 `round close` 가 부른다.
손으로 부를 때는 파일을 직접 친다.

| 관문 | 무엇을 보는가 | 왜 생겼나 |
|------|---------------|-----------|
| **좌표 감사** `node observatory/verify-coordinates.mjs` | **커밋되는 것에 「그 기계에만 있는 좌표」가 있는가.** 회사 이름을 열거하지 않고(§9) **구조로** 잰다 — 절대 경로(`/Users/…` · `/home/…` · `C:\…`)와 은하 좌표의 `path` 가 상대가 아닌 것. 로컬 명부(`galaxies.local/`)는 **안 본다** — 거기가 절대 경로가 사는 옳은 자리다 | MIT 로 공개하고 밀었더니 `galaxies/backoffice.json` 의 `path` 가 `/Users/<사람>/orca/…` 였다 — **남의 홈 경로가 공개 저장소에 올라가 있었다**(R152) |
| **3차 배선** `node observatory/verify-nebula-wiring.mjs` | 3차의 배선을 **모델 호출 0회**로 잰다. 미리 적어 둔 대본으로 돌려 **여덟**을 본다 — ① 범위 관문이 **별의 폴더 밖**을 막는가 ② 게이트 축 넷(lint·build·test·typecheck)이 **화면에 이름을 내는가** ③ 요구사항 신호가 **성공 출구에서** 찍히는가 ④ 빈 계약을 거부하는가 ⑤ 받은 계약을 못 고치게 막는가 ⑥ 재라고 했는데 못 쟀으면 초록불로 안 끝내는가 ⑦ **궤적에 레인이 적히는가** ⑧ **`extract` 가 그 대본을 카드 후보에서 빼는가**(R160) | 3차는 **가장 비싼데 가장 안 재지던 갈래**였다 — 실주행은 사람의 사용량을 쓰므로 관문에 못 넣는다. 대본은 같은 배선을 **공짜로** 지난다(R147) |

⚠️ ②가 셀 수 있게 된 것은 **R146 이 「안 돈 축은 화면에서 사라진다」를 고친 뒤**다.
`[SOLVED]` 한 줄만 보면 게이트가 한 칸도 안 돌아도 초록으로 읽힌다 — **축의 이름이 찍혔는가**로 잰다.

### 그 밖의 플래그

⚠️ `universe round close --dry-run` 은 **구현돼 있는데 §7 집행자 목록에서 빠져 거부됐다**(R87).
시키는 대로 쳤을 때 죽는 자리다. 그래서 아래 표는 손으로 관리하지 않는다 —
`universe args` 가 **받는 것 · 도구가 광고하는 것 · 이 문서**를 셋 다 대조한다.

| 명령 | 플래그 | 무엇을 하는가 |
|------|--------|---------------|
| `universe init` | `--update` | **판올림 경로.** 기계(배달되는 폴더)만 다시 깐다 — 은하·성운·로그는 손대지 않는다. `--force` 는 그것들을 지운다(R91). ⚠️ **새 법칙·힘·궤도가 생겼으면 목록에 이어 주고 무엇을 이었는지 말한다** — 목록에 있다는 것이지 켰다는 것이 아니다(R119·R120). 은하 목록은 안 건드린다 |
| `universe hooks` | `--uninstall` | 켠 커밋 관문을 끈다 |
| `universe round` | `--force` | 빨간 관문을 넘어 닫는다. **막지 않고 세어 기록한다**(R65) |
| `universe round` | `--dry-run` | 성운을 고치지 않고 판정만 본다 |
| `universe round which` | — | **어느 라운드가 열려 있는가.** mtime 으로 찾지 마라 — 복원이 그 값을 바꾼다(R88) |
| `universe round open` | — | **성운의 열린 줄을 오래된 순으로 내놓는다.** 손으로 grep 하지 마라 — 13줄로 세었는데 18줄이었다(R98) |
| `universe round close` | (frontmatter `closes:`) | 로그에 `closes: R89 변경 정직성 -> R95` 를 적으면 **성운 줄에 줄을 긋는다.** 못 찾으면 거부한다 — 「닫았다」고 적고 아무것도 안 닫히는 것을 막는다(R96) |
| `universe round` `universe lint` `universe observe` | `--why "<왜>"` | **기준선을 올릴 때** 사유. 없으면 안 올라간다 — 톱니는 내려가기만 쉽다 |
| `universe learn` | `--promote` | 궤적이 낸 후보를 성운에 붙인다 |
| `universe extract` | `--write` | **진짜로 뽑는다 — 모델을 궤적 한 건에 한 번 부른다.** 안 주면 무엇이 될지만 본다 |
| `universe extract` | `--galaxy <이름>` | 어느 은하의 궤적을 볼 것인가 |
| `universe orphans` | `--galaxy <이름>` | 한 은하만 본다 (안 주면 등록된 은하 전부) |
| `universe extract` | `--model <별칭>` | 카드를 뽑는 모델 (안 주면 엔진 기본) |
| `universe extract` | `--include-script` | **대본으로 돈 주행까지 뽑는다**(3차 팽창의 대본 레인). ⛔ 기본은 **뺀다** — 대본은 결정론이라 몇 번을 돌려도 하는 말이 같다. 실측(R159): 성공 176건 중 **175건이 같은 대본**이었고, 그대로 뽑으면 같은 카드 175장에 **모델 175번**이다 |
| `universe learn` | `--since <날짜>` | 볼 궤적의 범위를 자른다 (기본은 전부, 범위를 항상 찍는다) |
| `universe learn` `universe fix` `universe names` `universe enumeration` | `--update` | 지금 실측을 기준선으로 적는다 |
| `universe new` | `--base <커밋>` | 무엇이 새로 생겼는지 견줄 기준 커밋 |
| `universe new` | `--max-turns <수>` | (3차) 턴 예산. 기본 10 · 1~40. ⚠️ 진짜 은하는 조사에 턴이 많이 든다(실측: 10턴 중 7턴) |
| `universe new` | `--skills` | (3차) 지난 주행에서 뽑은 지식 카드를 브리핑에 넣는다. ⛔ **기본 꺼짐** — 결과를 낫게 하는지 아직 안 쟀다 |
| `universe new` | `--contract-first` | (3차) 요구사항을 **테스트로 먼저** 번역하고 **지금 빨간불인지** 확인한다. ⛔ **기본 꺼짐** |
| 전부 | `--universe <경로>` | 우주의 집을 직접 지정한다 (기본은 cwd 에서 탐색) |

내부 손잡이(`--model`·`--judge`·`--keep` 등)는 **문서에 안 적는 대신 사유를 적는다** —
`observatory/args-internal.json`. 사유 없이는 관문이 통과시키지 않는다.

## `render` / `publish` — 전파

```bash
universe render      # 우주 상태 → 발행본 7장
universe publish     # 위키로 (update — create 안 한다)
```

**방향은 한쪽뿐이다.** 저장소가 정본, 위키는 뷰. 위키에서 읽어 오지 않는다.

⚠️ 발행 전에 `observe` 가 초록불이어야 한다. **낡은 수치를 발행하는 것은 안 하느니만 못하다.**
